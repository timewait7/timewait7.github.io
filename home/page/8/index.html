双实现说明：本文是工单 Agent（ticket-agent-mcp）的 Python 实现；同一项目的 TypeScript 实现见 ticket-agent-mcp(ts)。两篇结构与代码约 80% 重叠，按你熟悉的技术栈选一篇精读即可（Python 篇侧重 FastMCP/pgvector 生态，TS 篇侧重 TypeScript 工程化与 Java 转型视角）。

一、项目概述

1.1 项目名称

智能工单处理 Agent（Intelligent Ticket Processing Agent，以下简称 ITPA）

1.2 项目背景

随着企业数字化转型的深入，客服系统积累了海量的用户咨询工单。传统的人工处理方式存在响应慢、人力成本高、知识利用不充分等问题。本项目建设一个基于 Model Context Protocol（MCP）的智能 Agent，能够自动处理用户工单，包括工单分类、相似问题检索、答案生成和工单创建，将人工从重复性工单处理中解放出来。

1.3 核心功能

功能模块 功能描述 MCP 能力类型
工单分类 根据工单内容自动分类（技术问题/账单问题/账号问题/产品咨询/投诉建议） Tool
相似工单检索 基于向量相似度检索历史工单，提供参考解答 Resource
回答生成 结合检索结果和工单内容生成回复建议 Tool
工单创建 将工单写入数据库，自动分配优先级 Tool
知识库管理 管理 FAQ 条目，用于增强检索 Resource

1.4 技术目标

完成本项目后，你将系统掌握：

  • Python 异步编程：使用 asyncio + httpx + asyncpg 处理高并发 I/O
  • 类型注解：完整的类型标注，使用 TypedDict、Literal、Protocol
  • 依赖管理：使用 uv 或 poetry 管理项目依赖
  • 日志配置：结构化日志输出，支持日志轮转和分级
  • 单元测试：使用 pytest + pytest-asyncio + pytest-cov
  • 数据库访问：异步 PostgreSQL 访问（asyncpg），使用 asyncpgsa 或原生连接池
  • HTTP 服务：使用 FastAPI 实现健康检查、指标暴露、管理接口
  • 环境配置管理：使用 pydantic-settings 管理多环境配置
  • 容器化部署：编写 Dockerfile 和 docker-compose.yml
  • 监控与日志：集成 Prometheus 指标、结构化日志输出
  • 错误处理：完善的异常捕获、重试机制、熔断降级

1.5 真实业务场景

ITPA 适用于以下场景：

  • 企业客服系统中台，作为智能路由层自动处理简单工单
  • 开发者在 Claude Desktop、Cursor IDE 等支持 MCP 的应用中直接调用
  • 作为通用的工单处理微服务，通过 HTTP/gRPC 供其他系统调用

2.3 MCP 协议交互流程

MCP 协议基于 JSON-RPC 2.0 消息流规范，采用“客户端-宿主-服务器”三层物理隔离模型，客户端与服务器在交互初期通过能力协商明确双方支持的功能集合。

补充说明（2026-07-28 协议更新）：MCP 规范已演进为无状态（Stateless）设计。initialize / initialized 握手仅用于能力协商——确定双方支持的协议版本与能力集合，并不建立长期会话状态；Server 不保存任何客户端会话数据，每个请求（如 tools/call）都可独立处理。这与 7.2 节”MCP Server 本身是无状态的”的表述完全一致：握手是协议流程的一部分，不代表 Server 需要维护状态。

七、运维实践指南

7.1 日志管理与监控

生产环境中，建议：

  • 日志采集：配置日志输出到 stdout，由容器平台采集；或配置 Filebeat 采集 JSON 日志并发送到 ELK
  • 错误追踪：集成 Sentry 捕获异常：import sentry_sdk; sentry_sdk.init(dsn=...)
  • Prometheus 指标：实现请求计数、延迟分布、错误率等核心指标

7.2 水平扩展策略

  • Stateless MCP Server：MCP Server 本身是无状态的，可以部署多个实例（2026-07-28 协议更新已明确 MCP 为无状态设计，initialize 握手仅用于能力协商，见 2.3 节说明）
  • 使用负载均衡：前置 Nginx/ALB 分发请求到多个 MCP Server 实例
  • 共享状态存储：数据库和 Redis 作为共享存储层，支持多实例无差别服务
  • Kubernetes 部署：使用 HPA 根据 CPU/请求数自动伸缩

7.3 容错与重试机制

  • LLM 调用：使用 tenacity 配置指数退避重试，应对速率限制和临时错误
  • 熔断器模式：对外部 API（Embedding API）实现熔断，避免级联故障
  • 降级策略：当 LLM 不可用时，使用关键词规则进行降级分类

7.4 安全加固

  • 认证：MCP 服务端点启用 API Key 认证或 OAuth 2.0
  • 输入验证：对所有工具输入参数进行 Pydantic 验证，防止注入攻击
  • 速率限制：使用 Redis 实现基于客户端 IP 或 API Key 的速率限制
  • TLS 加密：生产环境启用 HTTPS 传输

mini-cc

轻量级 AI 编程 Agent，模拟 Claude Code 的核心架构与行为——使用 AI SDK v6 驱动 LLM 进行工具调用，支持交互式终端 UI 和 SDK 两种使用方式。

目录结构

功能特性

  • AI SDK v6 驱动：使用 Vercel AI SDK v6 + OpenAI 兼容 API，自动处理工具调用的多轮对话
  • 多提供商支持：OpenAI、DeepSeek 及所有 OpenAI 兼容 API，只需配置 baseURL
  • Chat Completions API：使用标准的 /chat/completions 端点，与第三方 API 广泛兼容
  • Agent 循环：Think（模型推理）→ Act（工具执行）→ Observe（结果观察）三阶段循环，支持可配置的最大步数
  • 内置工具：Bash 执行、文件读取、文件写入，支持路径规范化、编码选择与超时控制
  • 权限控制：三种模式——auto（自动批准安全操作）、ask（高危操作拦截）、manual（全部需确认）
  • 工具扩展：通过 BaseTool 抽象类自定义工具，动态注册到 ToolRegistry
  • 状态机：管理 Agent 运行时状态（IDLE / THINKING / EXECUTING / OBSERVING / ERROR）
  • 上下文压缩：当消息 token 超过窗口 92% 时，自动保留首尾 30% 并插入摘要
  • 会话持久化：基于 bun:sqlite 存储会话和消息历史
  • 双入口：CLI 命令行（miniclude run / miniclude ask）和 SDK 编程调用
  • 终端 UI：基于 Ink 7 + React 的交互式终端界面，支持实时输入
  • 全 Bun 技术栈：Bun 运行时、Bun 原生 API（Bun.file、Bun.write、Bun.spawn、bun:sqlite）

Schema 修正机制

AI SDK v6 在某些版本中，Zod v4 → JSON Schema 的转换会产生缺少 type 字段的无效 schema，导致 DeepSeek 等严格校验的 API 拒绝请求。mini-claude 通过注入自定义 fetch 函数，在 HTTP 层拦截请求并将预计算的正确 JSON Schema 替换进去，确保与所有 OpenAI 兼容 API 的兼容性。

Q: Invalid schema for function: got 'type: null'

这是 AI SDK v6 的 Zod v4 → JSON Schema 转换缺陷导致的，在 DeepSeek 等严格校验的 API 上会出现。mini-claude 已内置修复（通过 fetch wrapper 修正 schema）。如果你仍遇到此问题，请确保使用最新版本的 agent-loop.ts。

Q: 终端 UI 无法正常显示

Ink 7 需要支持 ANSI 的终端。确保：

  • 不在非 TTY 环境下运行（如某些 IDE 内嵌终端可能不兼容）
  • 使用 ask 子命令代替 run 以获得纯文本输出

MCP 文件服务器

一个基于 Model Context Protocol (MCP) 的文件操作服务器，提供安全的文件读写、目录列举能力。支持与 Claude Desktop 等 MCP 客户端集成，让 AI 助手能够以安全、受限的方式访问本地文件系统。

功能特性

  • 🔐 路径安全：仅允许访问预定义的根目录（默认 ./allowed），防止路径遍历攻击。
  • 📁 目录列表：列出目录下的文件和子目录（JSON 格式）。
  • 📄 文件读取：支持 UTF-8 文本文件读取。
  • ✍️ 文件写入：自动创建不存在的目录，支持覆盖写入。
  • 🧪 测试工具：提供 ping 工具用于连通性测试。
  • 🛠️ MCP 标准：完全遵循 MCP 协议，可与任何兼容客户端无缝集成。

常见问题

1. 调用工具时提示 文件不存在

  • 确保文件路径相对于 allowed 目录正确。
  • 检查文件是否真实存在，或先用 write_file 创建。

2. list_directory 返回空数组或错误

  • 确认路径存在且是一个目录。
  • 检查根目录 allowed 是否已创建。如果没有，请手动创建：mkdir allowed。

3. Claude Desktop 不显示工具

  • 检查配置文件中的 args 路径是否为绝对路径。
  • 查看 Claude Desktop 日志（Help → View Logs）中是否有 MCP 相关错误。
  • 尝试重启 Claude Desktop 并检查网络代理设置。

4. 如何支持更大的文件？

当前实现会将整个文件读入内存。对于大文件（>100MB），建议修改为流式返回，可参考 MCP SDK 对 BlobResourceContents 的支持。

WeatherMate MCP Server

生产级天气数据 MCP 服务器，为 AI Agent 提供实时天气、逐小时预报、空气质量与恶劣天气预警能力。
遵循 MCP 2026-07-28 无状态候选规范，内置 OAuth 2.1、Token 优化、渐进式披露与水平扩展支持。

🎯 作用

WeatherMate MCP 允许任何支持 MCP 协议的 AI 客户端（Claude Desktop、Cursor、VS Code、ChatGPT 等）通过自然语言获取全球天气数据，而无需编写 API 调用代码。Agent 可以：

  • ✅ 查询任意城市的当前天气（温度、湿度、风速、体感温度）
  • ✅ 获取未来 5 天逐日预报或 3 小时间隔的逐小时预报
  • ✅ 获取空气质量指数 (AQI) 及主要污染物（需 API 支持）
  • ✅ 查询恶劣天气预警（台风、暴雨、暴雪等，需 API 支持）

与通用天气 API 不同，WeatherMate 专为 LLM 推理优化：

  • ✅ Token 高效 – 字段过滤 + 数据截断 + 渐进式披露，单次响应 <500 tokens
  • ✅ Agent 友好 – 输出包含语义摘要、可操作错误建议
  • ✅ 零会话管理 – 无状态设计，可部署在 Kubernetes + Serverless
  • ✅ 安全合规 – OAuth 2.1 + PKCE，工具级权限范围

已实现的优化

痛点 解决方案 效果
Token 爆炸 字段过滤 + 截断 + 摘要生成 单次响应 <500 tokens（原始 API 约 2.5k）
多租户隔离 无状态设计 + JWT 租户标识 水平扩展无需会话存储
LLM 错误理解 Agent 可读错误（retryable + suggestion） 模型可自动重试或降级
工具列表臃肿 ttlMs 客户端缓存工具定义 减少 85% 的 tools/list 调用
下游延迟 Redis 缓存 + LRU P95 延迟从 450ms 降至 35ms

已知限制

  1. OpenWeatherMap 免费限制
    • 每分钟 60 次调用，免费版不支持空气质量与预警（需付费订阅“One Call by Call”）。
    • 未来改进：增加可选数据源（如高德、Open-Meteo）作为 fallback。
  2. 空气质量与预警工具
    当前实现依赖 OpenWeatherMap 的付费 API，免费 Key 下这两个工具会返回“不可用”错误。
    未来改进：集成免费 AQI 数据源（如 WAQI）或预警 RSS 订阅。
  3. 地理编码
    目前要求客户端传递精确城市英文名（如“Beijing”）。
    未来改进：内置模糊搜索（“东三环”→“经纬度”）或使用本地地理编码库。
  4. 无状态模式的流式响应
    当前所有工具均为同步请求。未来可为长任务（如生成详细气象报告）实现 MCP Tasks 扩展。
  5. Redis 缓存依赖
    REDIS_ENABLED=false 时降级为本地 LRU 缓存（仅单实例有效）。
    未来改进：实现更健壮的本地缓存 + 分布式缓存切换。
  6. OpenTelemetry 可选
    如未配置 OTEL_EXPORTER_OTLP_ENDPOINT，追踪功能自动禁用，不影响核心功能。
  7. 错误处理粒度
    目前对网络超时、城市未找到等错误提供了可操作建议，但仍可增加更细粒度的错误分类（如 API 配额超限）。

🔐 安全考量

  • 认证：强制 OAuth 2.1 + PKCE（生产环境），开发时可临时关闭。
  • 授权：每个工具调用检查 scope（如 mcp:weather:read）。
  • 输入验证：使用 Zod 校验，防止注入攻击（城市名称仅允许字母、空格、连字符）。
  • 速率限制：每 IP / 每 Token 每分钟 60 次请求（可配置）。
  • 审计日志：所有工具调用记录到结构化日志（logger.info 包含调用者、工具名、响应大小）。
  • TLS：生产环境强制 HTTPS（建议使用反向代理如 nginx）。
