文本处理三剑客：grep、sed、awk

Posted on 2025-01-08 In 开发工具 Word count in article: 4k Reading time ≈ 15 mins.

概述：三个工具的分工

Linux 文本处理三剑客 grep、sed、awk，是后端开发天天要用的三个命令行工具：查日志、批量改配置、统计接口调用量，处处都有它们的身影。三者分工一句话：grep 负责「找」，sed 负责「改」，awk 负责「算」。

工具 定位 一句话 名字由来
grep 搜索 找出匹配的行，只读不改 global regular expression print
sed 编辑 按行流式增删改，输出到屏幕 stream editor
awk 数据处理 按分隔符切分字段，统计、计算、格式化 作者 Aho、Weinberger、Kernighan 姓氏首字母

选型口诀：要看哪些行用 grep，要动哪些行用 sed，要对行内字段算账用 awk。

三者天然适合管道串联：grep 负责筛选、awk 负责计算、sed 负责排版，各干各的活。

grep：查找，只读不改

1. 常用参数速查（实战重点）

grep 从文件或标准输入中逐行读取文本，按模式匹配每一行，把匹配的行输出到标准输出，不修改原文件。基本语法：

选项 说明 示例
-i 忽略大小写 grep -i error app.log
-v 反向匹配，输出不匹配的行 grep -v '#' config
-E 扩展正则（ERE），等价 egrep grep -E 'A|B' file
-P Perl 兼容正则（PCRE），支持 \d grep -P '\d+\.\d+'
-c 只统计匹配行数 grep -c 'ERROR' app.log
-n 显示行号 grep -n 'TODO' Main.java
-r / -R 递归搜索目录（-R 跟随符号链接） grep -r 'TODO' src/
-l / -L 只输出含 / 不含匹配的文件名 grep -rl 'RedisTemplate' src
-o 只输出匹配到的部分 grep -oP '\w+Exception'
-w 整词匹配，防止匹配到子串 grep -w 'order' file
-q 静默模式，不输出，只看退出码 if grep -q 'x' f; then
-e 指定多个模式（或匹配以 - 开头的模式） grep -e ERROR -e timeout
-A n / -B n / -C n 输出匹配行后 n 行 / 前 n 行 / 前后各 n 行 grep -C 5 'OOM' app.log
-F 按固定字符串匹配，模式中的元字符不解析 grep -F 'a+b' file

2. 正则表达式速查

grep 默认使用基础正则（BRE），-E 切换为扩展正则（ERE），-P 使用 Perl 兼容正则（PCRE）。三者核心差异在元字符是否需要转义：

语法 BRE ERE（-E） PCRE（-P）
或 |（需转义） ` `
分组 \(...\)（需转义） (...) (...)
量词 + ? {n,m} 需转义（\+ 等） 直接使用 直接使用
预定义字符类（\d \w \s） 不支持 不支持 支持
懒惰匹配（.*?） 不支持 不支持 支持

小技巧：日常写 grep 一律加 -E，省去转义的麻烦；要匹配数字、单词字符这类短写法时用 -P。

常用元字符：

元字符 含义 示例
. 任意单个字符 grep -E 'a.c' 匹配 abc、a1c
* 前一个字符重复 0 次或多次 colou*r 匹配 color、colour
+ 前一个字符重复 1 次或多次 go+d 匹配 god、good
? 前一个字符出现 0 次或 1 次 colour? 匹配 color、colour
{n,m} 重复 n 到 m 次 [0-9]{3} 匹配三位数字
^ / $ 行首 / 行尾锚定 ^2024- 匹配以 2024- 开头的行
[...] 字符集 [0-9]、[a-zA-Z]、[^0-9]（取反）
(...) 分组 (ab)+ 匹配 ab、abab
| / ` ` 或（BRE 需转义）
\b 单词边界（PCRE） \bcat\b

3. 退出码：脚本里的隐形返回值

grep 的退出码在脚本中非常有用：0 有匹配，1 无匹配，2 出错（如文件不存在）。

sed：流式编辑，增删改查

1. 执行模型

sed 是流式编辑器（stream editor），按行处理：一次从输入读一行 → 按地址匹配命令 → 执行修改 → 输出，然后读下一行，如此循环。它不像 vi 需要打开文件，可以直接处理管道里的数据流，所以叫「流式」。

处理过程中，当前行存放在模式空间（pattern space）；另有保持空间（hold space）可临时存数据，配合 h、g、x 等命令可以做跨行操作（如倒序输出）。实际开发中保持空间用得少，知道存在即可。

2. 地址寻址：让命令只作用于部分行

默认 sed 命令作用于所有行；用地址限定作用范围：

地址形式 作用范围 示例
n 第 n 行 sed '3d' file 删第 3 行
n,m 第 n 到 m 行 sed '2,5d' file
n,$ 第 n 行到文件结尾 sed '2,$d' file
/pattern/ 匹配该模式的行 sed '/^$/d' file 删空行
/p1/,/p2/ 从匹配 p1 的行到匹配 p2 的行 sed -n '/BEGIN/,/END/p'
地址!命令 取反，对不匹配的行执行 sed '/^#/!d' file

3. 增删改查：四个核心操作（实战重点）

sed 的全部能力可以浓缩成增、删、改、查四个操作：

操作 命令 示例 说明
增 a（append） sed '3a 新行' file 在第 3 行之后追加
增 i（insert） sed '3i 新行' file 在第 3 行之前插入
删 d（delete） sed '3d' file 删除第 3 行
改 s（substitute） sed 's/旧/新/g' file 替换行内文本
改 c（change） sed '3c 新行' file 整行替换
查 p（print） sed -n '3p' file 打印第 3 行（常配 -n）

注意 s 默认只替换每行第一处匹配，加标志 g 才替换全部：

4. 替换进阶：标志、分组与特殊字符

s/pattern/replacement/flags 的 flags 速查：

flag 作用
g 替换行内所有匹配
n（数字） 只替换第 n 处匹配
p 打印替换后的行（配 -n）
i 忽略大小写
w file 把替换后的行写入文件

replacement 中的两个特殊记号：

  • &：引用整个匹配的文本
  • \1、\2：引用第 1、2 个分组捕获的内容（配 -E）

6. 实战：常用一行流

awk：字段级数据处理

1. 执行模型：BEGIN / 主循环 / END（面试核心考点）

awk 本身是一门小语言，由若干 pattern { action } 规则组成。执行模型是：读一行 → 匹配规则 → 执行动作，循环往复；另有 BEGIN、END 两个特殊阶段，各执行一次。

flowchart TD
    A[Start] --> B[BEGIN block: init vars, set FS, print header]
    B --> C[Read one record]
    C --> D{EOF?}
    D -- No --> E[Match patterns and run actions]
    E --> F[Next record]
    F --> C
    D -- Yes --> G[END block: print summary stats]
    G --> H[Exit]

这对应 Java 里「初始化 → 逐条处理 → 汇总」的写法，理解成本很低。

2. 字段处理：$0 与 $n

awk 自动把每一行按分隔符切分成字段，用 $n 访问：

变量 含义
$0 整行文本
$1、$2 … 第 1、2 个字段
$NF 最后一个字段（NF 是字段总数，见下节）

3. 内置变量速查（NF / NR / FS）

变量 含义 典型用途
NF 当前行的字段总数 $NF 取最后一个字段
NR 已处理的记录总数（跨文件累计） 输出行号、跳过表头
FNR 当前文件内的记录数 多文件处理时区分
FS 输入字段分隔符，默认空白 BEGIN{FS=","}
OFS 输出字段分隔符，默认空格 让 print 的输出用 `
RS 输入记录分隔符，默认换行 处理跨行记录
ORS 输出记录分隔符，默认换行 —
FILENAME 当前输入文件名 多文件合并处理
$0 整行 原样输出

面试考点：NR 和 FNR 的区别——NR 是全局累计的行号，FNR 是当前文件内的行号；同时处理多个文件时，文件切换后 FNR 归零、NR 不归零。

4. 模式匹配与统计实战（实战重点）

awk 的 pattern 可以是正则、比较表达式，也支持 if、for 等流程控制和 printf 格式化输出。

三剑客组合实战

实际排查问题从来不是单用一个工具，而是管道串联。最典型的场景：从 access.log 里统计返回 5xx 最多的前 5 个 IP。

flowchart LR
    A[app.log] --> B[grep: filter 5xx lines]
    B --> C[awk: split fields, count by IP]
    C --> D[sort / uniq / head: rank top N]
    D --> E[awk printf / sed: format output]

每一步的职责拆开看：

步骤 工具 职责
1 grep 筛出 5xx 的响应行（只读，不改）
2 awk 按空格切字段，取 IP 计数（Map 累加）
3 sort / head 按次数降序排，取前 5
4 awk printf 格式化成对齐报表

另一个常见组合是按时间段取日志并统计：sed 负责按时间范围切段，awk 负责段内统计。

总结与避坑清单

回到开头那句话：grep 找行、sed 改行、awk 算字段。排查一次线上问题，往往是 grep 定位 → sed 切段 → awk 统计 三步流水线。把三张速查卡记熟，日志分析效率能上一个台阶。

常见坑 原因 处理
grep 里 ` ` 不生效 默认是 BRE，`
s/test/trial/ 只换了一处 s 默认只替换行内第一处 加 g
sed 改了原文件找不回 没备份直接 -i 用 -i.bak，回滚只需 mv
替换时 & 变成整个匹配 replacement 里 & 是特殊记号 要字面量就写 \&
ps aux | grep java 多出自身进程 grep 匹配到了自己 加 -v grep 或用 pgrep
中文日志 grep 不到 文件是 GBK 编码 先 iconv -f GBK -t UTF-8 再 grep
统计脚本慢 循环里反复调用 grep 换成 awk '{cnt[$1]++} END{...}' 一次读完

Docker 容器实战

Posted on 2024-12-16 In 部署运维 Word count in article: 11k Reading time ≈ 38 mins.

1. Docker 解决什么问题

“在我机器上能跑啊？” —— 开发环境装好了、测试也通过了，换一台机器（同事的电脑、测试服务器、生产服务器）就各种报错：JDK 版本不对、依赖缺失、系统库没有、配置文件忘改……环境差异是软件交付路上最常见的坑。

Docker 的解法是：把应用和它的完整运行环境（代码、运行时、依赖、配置、启动脚本）一起打包成一个镜像（Image）。镜像是不可变的、自包含的，在任何装了 Docker 的机器上，都能以完全一致的方式运行 —— 这就是 一次构建，处处运行（Build Once, Run Anywhere），彻底告别在我机器上能跑。

和虚拟机相比，Docker 共享宿主机内核、以进程级隔离运行，因此：

对比 Docker 容器 虚拟机
隔离粒度 进程级（共享内核） 整机级（完整操作系统）
启动速度 秒级 分钟级
镜像/磁盘占用 几十 MB ~ 几百 MB 几个 GB 起步
单机密度 轻松几十上百个 通常个位数

虚拟机每个都是完整操作系统，隔离更强但也更重；容器共享内核，更轻更快，但必须在 Linux 上运行（macOS/Windows 通过虚拟机跑 Linux 内核间接运行），且隔离强度弱于虚拟机 —— 运行不可信代码等安全要求极高的场景仍需虚拟机。

1. Linux 是什么

Linux 最初只是一个开源的操作系统内核（Kernel）。我们日常所说的”Linux 系统”，指的是 Linux 内核 + GNU 工具集等周边软件组成的完整可用系统，这类组合统称为发行版（Distribution），如 Ubuntu、Debian、CentOS、RHEL 等。

发行版之间的主要区别：

  • 包管理器不同：Debian 系（Ubuntu/Debian）用 apt，RedHat 系（CentOS/RHEL/Fedora）用 yum/dnf，Arch 系用 pacman。命令名不同，但理念一致——装包、卸包、更新、搜索
  • 预装软件和发布节奏不同（有的求稳、有的求新）

为什么服务器几乎都是 Linux：

  • 开源免费，没有授权费
  • 稳定：可以不重启连续运行数月甚至数年
  • 轻量：不需要图形界面，低配机器也能跑
  • 远程友好：SSH 登录即用，天然适合无头（headless）管理
  • 生态垄断：Nginx、MySQL、Docker、K8s 等服务端软件都优先支持 Linux
