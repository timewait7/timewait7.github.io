Maven 依赖管理精要

Posted on 2025-02-26 Word count in article: 953 Reading time ≈ 3 mins.

Maven

Maven 是一个 项目管理和构建工具，主要用于 Java 项目的依赖管理、构建自动化以及项目生命周期管理。

依赖范围

scope 元素声明依赖的作用范围，决定依赖在编译、测试、运行哪个阶段可见：

依赖范围 说明
compile scope元素的缺省值。编译、测试、运行阶段都会引入
test 测试阶段引入
provided 编译、测试阶段引入，运行期由容器（如 Tomcat 的 servlet-api）提供
runtime 测试、运行阶段引入，编译期不需要（如 JDBC 驱动）
system 用于添加本地依赖，不推荐使用
import 与 dependencyManagement 元素配合使用，其功能是将目标 pom.xml 文件中 dependencyManagement 的配置导入合并到当前 pom.xml 的 dependencyManagement 中

依赖传递

有三个模块A、B、C，A依赖B，B依赖C，C是否能传递到A，取决于B依赖C时使用的依赖范围和配置。

传递规则：

B 依赖 C 时的范围 能否传递到 A 说明
compile 可以传递 C 会被 A 引入，且对 A 编译可见
runtime 可以传递 C 会被 A 引入，但仅在 A 运行时可见
test 不可以传递 test 范围只对声明它的模块（B）的测试生效
provided 不可以传递 由运行环境提供，无需向下游传递
system 不可以传递 本地 jar，不参与传递

optional 为 true 的依赖不能传递：

optional 表示该依赖只是当前模块的可选实现（如 SLF4J 的多个绑定、数据库驱动的多种实现），下游模块需要使用时必须自行显式声明，避免传递出无用的依赖。

依赖冲突

当直接依赖和间接依赖引用了同一个依赖的不同版本时，最终生效的版本由 Maven 的依赖调解决定：

  • 最短路径原则

A 到 jackson-databind 有两条依赖路径：A->B->C->jackson-databind（如 2.14.0）和 A->jackson-databind（如 2.15.0）。路径短的胜出，最终 A 依赖 jackson-databind 的 2.15.0 版本。

  • 声明顺序原则

当 A 到 jackson-databind 的依赖路径长度一样（A->B->jackson-databind 和 A->C->jackson-databind）时，最短路径原则不适用。此时先声明的依赖生效：B 先声明则使用 B 传递的版本，C 先声明则使用 C 传递的版本。

  • 排除传递依赖：exclusions

如果不想让某个传递依赖进入依赖树，可以用 exclusions 显式排除：

常用于：排除重复的日志实现、排除冲突的传递版本、精简依赖树。

dependencyManagement：统一管理依赖版本

dependencyManagement 的作用是只声明版本，不引入依赖。子模块声明同名依赖（不写版本号）时，统一使用这里声明的版本：

使用要点：

  • 父模块集中声明所有依赖的版本，子模块引用同名依赖时**无需再写 version**，实现多模块版本统一管理，避免版本不一致。
  • 子模块可以覆盖父模块声明的版本（显式写上 version 即可）。
  • 与 import 范围配合可以导入 BOM（如 Spring Boot 的 spring-boot-dependencies），导入后当前 pom 即拥有 BOM 中全部依赖的版本声明。

依赖冲突解决优先级（从高到低）：

  1. dependencyManagement 中声明的版本（强制指定，优先于依赖调解结果，除非子模块显式覆盖）
  2. 最短路径原则
  3. 声明顺序原则

exclusions 不参与版本选择，用于在规则之外手动剔除多余的传递依赖。

本文脚本中反复出现以下良好实践，编写新运维脚本时可直接套用。

错误处理：set -euo pipefail

  • set -e：任一命令返回非零立即退出（2.4 deploy-java.sh 已使用，可升级为完整版）
  • set -u：引用未定义变量直接报错，拼写错误无处遁形
  • set -o pipefail：管道中前面命令失败时整体仍算失败——典型场景是 grep 无匹配返回非零（见 2.3 log-analyzer.sh 中 grep -c 的处理注释）
  • 注意：开启 set -e 后，需要捕获退出码的场景要用 cmd; ret=$? 先存后判——$? 只保留上一条命令的退出码，直接连用会丢失前面的结果（见 2.2 服务健康检查 中 process_ok=$? 的写法）

日志规范：时间戳 + 级别

统一 [级别] 时间 消息 格式，方便按级别 grep 检索：

  • 彩色输出可参考 2.4 deploy-java.sh 的 log_info/log_warn/log_error（重定向到文件时退化为纯文本）

文本处理三剑客：grep、sed、awk

Posted on 2025-01-08 In Linux Word count in article: 8k Reading time ≈ 29 mins.

1. 概述：三个工具的定位

Linux 文本处理三剑客 grep、sed、awk，分工一句话：

工具 定位 一句话
grep 搜索 在文本中查找匹配的行，只读不改
sed 编辑 流式编辑，按行读入并执行增、删、改、替换
awk 数据处理 按分隔符切分字段，支持变量、数组与流程控制，擅长统计和格式化

一句话区分：要找出哪些行，用 grep；要改动哪些行，用 sed；要对行内的字段算账，用 awk。 三者经常通过管道串联使用，例如 grep ERROR app.log | awk '{print $2}' | sort | uniq -c，grep 负责筛选、awk 负责计算、sed 负责排版。

2. grep

2.1 基本语法与常用选项

grep 从文件或标准输入中逐行读取文本，按模式匹配每一行，将匹配的行输出到标准输出：

常用选项：

选项 说明
-i 忽略大小写
-v 反向匹配，输出不匹配的行
-r / -R 递归搜索目录（-R 会跟随符号链接）
-l / -L 只输出包含 / 不包含匹配内容的文件名
-n 显示匹配行的行号
-c 只统计匹配的行数
-A n 输出匹配行及其后 n 行（after）
-B n 输出匹配行及其前 n 行（before）
-C n 输出匹配行及其前后各 n 行（context）
-E 使用扩展正则表达式（等价于 egrep）
-P 使用 Perl 兼容正则表达式（PCRE）
-o 只输出匹配到的部分，而不是整行
-w 整词匹配
-q 静默模式，不输出任何内容，只返回退出码
-e 指定多个匹配模式（或匹配以 - 开头的模式）

grep 的退出码在脚本中很有用：0 表示有匹配，1 表示无匹配，2 表示出错。

2.2 正则表达式速查

grep 默认使用基础正则表达式（BRE），-E 切换为扩展正则表达式（ERE），-P 使用 Perl 兼容正则（PCRE）。三者的主要差异在于元字符是否需要转义：

语法 基础正则（BRE） 扩展正则（ERE） Perl 正则（PCRE）
或 |（需转义） ` `
分组 \(...\)（需转义） (...) (...)
量词 + ? {n,m} 需转义（\+ 等） 直接使用 直接使用
预定义字符类（\d \w \s） 不支持 不支持 支持
懒惰匹配（.*?） 不支持 不支持 支持

常用元字符：

元字符 含义
. 匹配任意单个字符
* 前面的字符重复 0 次或多次
+ 前面的字符重复 1 次或多次（ERE/PCRE）
? 前面的字符出现 0 次或 1 次（ERE/PCRE）
^ / $ 行首 / 行尾锚定
[...] 字符集，如 [0-9]、[a-zA-Z]、[^0-9]（取反）
\(...\) / (...) 分组捕获
| / ` `
\< / \> 单词首 / 单词尾锚定（BRE）

3. sed

3.1 执行模型

sed 编辑器可以根据命令来处理数据流中的数据，这些命令要么从命令行中输入，要么存储在一个文本文件中。sed 编辑器会执行下列操作：

  1. 一次从输入中读取一行数据。
  2. 根据所提供的编辑器命令匹配数据。
  3. 按照命令修改流中的数据。
  4. 将新的数据输出到 STDOUT 或文件中。

模式空间和保持空间

模式空间（Pattern Space）是当前工作的空间，sed 编辑器会将数据流中文本行读入到模式空间进行处理。保持空间（Hold Space）可以看作是模式空间的备份空间，可以将模式空间的某些行临时存储在保持空间，之后再将这些行从保持空间移回模式空间。

模式空间和保持空间的交互命令如下：

命令 描述
h 将模式空间复制到保持空间
H 将模式空间附加到保持空间
g 将保持空间复制到模式空间
G 将保持空间附加到模式空间
x 交换两个空间的内容

地址

默认情况下，在 sed 编辑器中使用的命令会作用于文本数据的所有行。如果只想将命令作用于特定行或某些行，则必须用行寻址（line addressing）。在 sed 编辑器中有两种形式的行寻址：

  • 以数字形式表示行区间
  • 用文本模式来过滤出行

数字形式行寻址

  • 指定某行：sed '2command' file
  • 指定行区间：sed '2,3command' file
  • 从某行开始到结尾：sed '2,$command' file

文本模式行寻址

  • 匹配某行：sed '/pattern/command' file
  • 匹配行区间：sed '/start/[,/end/]command' file

4. awk

gawk 程序是 Unix 中原始 awk 程序的 GNU 版本，其报告生成能力通常用来从大文本文件中提取元素，并将它们格式化成可读的格式，如格式化日志文件。

gawk 的命令格式为：gawk options program file。

常用的选项如下：

选项 说明
-F fs 指定行中划分数据字段的字段分隔符
-f file 从指定的文件中读取程序

-mf N 指定要处理的数据文件中的最大字段数
-mr N 指定数据文件中的最大数据行数
-W keyword 指定 gawk 的兼容模式或警告等级

4.1 执行模型：BEGIN / 主循环 / END

awk 程序由若干条 pattern { action } 规则组成，其执行模型是：读一行 → 匹配规则 → 执行动作，循环往复。除此之外还有两个特殊模式，分别在处理开始前和结束后各执行一次：

  • **BEGIN { action }**：在读取任何输入之前执行一次。通常用于初始化变量、设置 FS 分隔符、打印表头。
  • 主循环：逐行读取输入，对每一行依次匹配各条规则，匹配成功则执行对应的 action。
  • **END { action }**：所有输入处理完之后执行一次。通常用于输出汇总统计结果。

4.2 内建变量与自定义变量

所有编程语言都可以使用变量来存取值，gawk 编程语言支持两种类型变量：

  • 自定义变量

数据字段变量

在处理文本时，gawk 会给一行中的每个数据元素分配一个变量：

  • $0：表示整个文本行
  • $1：表示第1个数据字段
  • $n：表示第n个数据字段

分隔符变量

gawk 默认采用空白字符作为输入和输出字段分隔符。

变量 描述
FIELDWIDTHS 由空格分隔的一列数字，定义了每个数据字段确切宽度
FS 输入字段分隔符
RS 输入记录分隔符
OFS 输出字段分隔符
ORS 输出记录分隔符
  • 通过 FS 指定输入字段分隔符
  • 通过 OFS 指定输出字段分隔符
  • 通过 FIELDWIDTHS 变量来匹配数据在记录中的位置

在一些应用程序中，数据并没有使用字段分隔符，而是被放置在了记录中的特定列。这种情况下，必须设定 FIELDWIDTHS 变量来匹配数据在记录中的位置。一旦设置了 FIELDWIDTHS 变量，gawk 就会忽略 FS 变量，并根据提供的字段宽度来计算字段。

  • 通过 RS 指定输入记录分隔符

Docker 容器实战

Posted on 2024-12-16 In 容器 Word count in article: 11k Reading time ≈ 39 mins.

1. Docker 解决什么问题

“在我机器上能跑啊？” —— 开发环境装好了、测试也通过了，换一台机器（同事的电脑、测试服务器、生产服务器）就各种报错：JDK 版本不对、依赖缺失、系统库没有、配置文件忘改……环境差异是软件交付路上最常见的坑。

Docker 的解法是：把应用和它的完整运行环境（代码、运行时、依赖、配置、启动脚本）一起打包成一个镜像（Image）。镜像是不可变的、自包含的，在任何装了 Docker 的机器上，都能以完全一致的方式运行 —— 这就是 一次构建，处处运行（Build Once, Run Anywhere），彻底告别在我机器上能跑。

和虚拟机相比，Docker 共享宿主机内核、以进程级隔离运行，因此：

对比 Docker 容器 虚拟机
隔离粒度 进程级（共享内核） 整机级（完整操作系统）
启动速度 秒级 分钟级
镜像/磁盘占用 几十 MB ~ 几百 MB 几个 GB 起步
单机密度 轻松几十上百个 通常个位数

虚拟机每个都是完整操作系统，隔离更强但也更重；容器共享内核，更轻更快，但必须在 Linux 上运行（macOS/Windows 通过虚拟机跑 Linux 内核间接运行），且隔离强度弱于虚拟机 —— 运行不可信代码等安全要求极高的场景仍需虚拟机。
