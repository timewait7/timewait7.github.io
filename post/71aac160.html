ticket-agent-mcp(ts)

Posted on 2026-06-08 In AI大模型 Word count in article: 6.6k Reading time ≈ 24 mins.

文档说明：本文标题为”智能客服 MCP”，所描述的项目实为 ticket-agent-mcp（智能工单处理 Agent）的 TypeScript 实现版本；姊妹文档 ticket-agent-mcp(py) 是其 Python 实现版本。两篇结构与代码约 80% 重叠，按你熟悉的技术栈选一篇精读即可——本文（TS 版）以 TypeScript 工程化与 Java 转型视角为特色，业务代码（分类/生成 Prompt）较 Python 版更完整。

项目设计总览

维度 选型 理由（面向 Java 开发者）
语言 TypeScript 5.x 静态类型，类似 Java 的类型安全，但更具表达力
Runtime Bun 1.x 原生 TS 支持，一体化工具链（包管理、测试、运行），开发体验类似 Maven 但更快
依赖管理 Bun 内置 无需单独安装 npm/yarn，bun install 开箱即用
Web 框架 Fastify 高性能（可对标 Netty），内置 JSON Schema 验证，类似 Spring Boot 的插件架构
ORM TypeORM 最接近 JPA/Hibernate 体验的 TS ORM，支持 Active Record 和 Data Mapper
数据库 MySQL 8.0 符合你的要求，支持向量存储（通过 MySQL HeatWave 或独立向量库）
MCP SDK @modelcontextprotocol/sdk Anthropic 官方 TypeScript SDK
日志 Pino 结构化 JSON 日志，性能极高，类似 Logback 但输出格式更现代
验证/配置 Zod + dotenv 类似 Java Bean Validation + Spring Boot 配置绑定的体验
测试 Bun 内置 + Vitest Bun 自带测试运行器，开发测试一体化
代码规范 ESLint + Prettier 类似 Checkstyle/Spotless 的体验
容器化 Docker + Docker Compose 统一部署

现在，让我们从一个具体的业务场景开始。

第一部分：项目愿景与业务场景

1.1 真实业务痛点

设想一个典型的中大型企业客服场景：

每天接收 500+ 用户工单，涵盖技术问题、账单疑问、账户申诉、产品咨询、投诉反馈五大类。纯人工处理方式带来三个核心痛点：响应速度慢、人力成本高、知识资产沉淀困难。

本项目构建的 智能工单处理 Agent（ITPA） ，将接入企业的现有工单系统，自动完成以下任务：

  • 自动分类：根据工单标题和内容，智能识别属于哪一类问题
  • 相似历史检索：基于向量相似度，检索过往已解决的相似工单作为参考
  • 自动生成回复：结合检索结果，生成可供人工审批的回复草稿
  • 创建工单记录：将工单写入数据库，自动分配优先级和处理人

1.2 为什么选择这个项目作为转型跳板？

  • 全链路覆盖：从 HTTP 接收入口 → 分类判断 → 向量检索 → LLM 生成 → 数据库落库，体验完整的”请求-处理-响应”链路
  • AI 原生体验：真实调用 LLM API（OpenAI 或本地模型），理解 AI 应用的核心模式
  • 生产级复杂度：涉及向量检索、JSON Schema 验证、结构化日志、连接池管理、健康检查等生产必需能力
  • 可平滑演进：从本地 stdio 模式起步，无缝切换至 HTTP 模式的分布式 MCP Server

2.3 MCP 协议核心概念

MCP（Model Context Protocol）是 Anthropic 于 2024 年 11 月推出的开放标准，旨在统一 AI 应用的”工具使用”方式，它定义了三个核心原语：

原语 类比 说明
Tools RPC 远程调用 可被 AI 调用的函数，有明确的输入输出 schema
Resources REST 资源 只读数据源，AI 可按需读取
Prompts 模板引擎 可复用的提示词模板，用户可手动调用

MCP 支持两种传输方式：STDIO（本地进程通信）和 Streamable HTTP（远程部署）。经过测试，在数据库查询处理性能上 Node.js 比 Bun 有约 1.19 倍的领先；而作为 TypeScript 运行时，Bun 的启动速度快约 10 倍（10ms vs 100ms），运行时快 2-4 倍。这也印证了本项目选择混合运行时策略的合理性。

第五部分：TypeScript 工程化配置

5.1 为什么选 Bun 而非 Node.js？

作为 Java 开发者，你可能习惯 Maven/Gradle 这种”一个工具链搞定一切”的体验。Bun 正是提供了这种全栈式体验的 JavaScript 运行时：

能力 Node.js 方式 Bun 方式 Java 类比
包管理 npm/yarn/pnpm 三选一 bun install Maven 依赖
运行 TS ts-node 或 node --loader ts-node bun run 原生 TS 直接运行 Java
测试 Jest/Vitest/Mocha bun test 内置 JUnit
打包 Webpack/esbuild/rollup bun build 内置 Maven Shade
类型检查 需单独运行 tsc bun --bun run tsc 编译器自动检查

TypeScript 原生支持：Bun 原生支持 TypeScript，无需额外配置。Node.js 从 v22.6.0 开始也支持内置类型剥离，但 Bun 的集成更彻底，开发者体验更流畅。

性能优势：Bun 冷启动时间约 10ms，而 Node.js 约 100ms；运行时执行效率是 Node.js 的 2-4 倍。

一体化体验：Bun 将包管理器、测试运行器、打包工具整合到一个平台，让你从”需要组合几十个工具”的困扰中解放出来。
