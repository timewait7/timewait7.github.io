Zeus-Doc 启动与部署运维实战

本手册覆盖从零启动 Zeus-Doc 到 K8s 生产部署的全流程。提供两种启动模式：

  • 模式一（推荐）：最小化启动 —— 资源受限环境（8GB 内存 / Docker 3.84GB）实测可整体运行，覆盖核心功能；
  • 模式二：全功能启动 —— 启动全部 15 个中间件 + 7 个微服务（含主从复制、协同编辑、文件上传、SkyWalking、压测监控栈）。

相关文章：架构详见《Zeus-Doc 架构设计与技术选型》，性能调优见《Zeus-Doc 性能压测实战》与《Zeus-Doc JVM 调优与 OOM 排查》，压测环境与线程模型见《Zeus-Doc 高并发线程与锁设计》。

三、模式一：最小化启动

3.1 功能边界与资源预算

启动组件： 6 个核心中间件（Docker）+ 5 个微服务（宿主 JVM）：

组件 说明
中间件 MySQL 8.0（buffer_pool 128M）、Redis 7（128mb 关 AOF）、Nacos 2.3（256m）、Elasticsearch 8.11（256m）、RocketMQ 5.1.3（128/256m）、Seata 1.7（256m）
微服务 Gateway(9000) / User(9001) / Doc(9002) / Search(9004) / Audit(9006)，JVM 统一 -Xmx256m

内存预算（8GB 机器实测可运行）：

  • Docker 中间件 ≈ 2.8GB（≤ 3.84GB 分配上限）
  • 宿主 JVM 5 个 ≈ 1.5GB
  • 合计 ≈ 4.3GB，系统其余留 3.7GB 缓冲

四、模式二：全功能启动

全量启动 15 个中间件 + 7 个微服务，约 30 分钟可完整拉起。本机内存低于 16GB 时不建议。

4.1 启动全部中间件

包含：MySQL 主从（3306/3307）、Redis、Nacos、ES、RocketMQ、MinIO、Seata、Sentinel、
SkyWalking（OAP+UI）、ZooKeeper、压测监控栈（InfluxDB/Prometheus/Node-Exporter/Grafana）共 15 个服务。

中间件端口与凭据：

Nacos 8848 / 9848 控制台登录 nacos / nacos（默认）；身份密钥 zeus / zeus-nacos-2024 gRPC 端口 9848 必须开放

⚠️ 首次启动注意事项：

  1. 从库依赖主库健康，主库 initdb 耗时 3-5 分钟，期间 docker compose up 可能中断，属正常现象——
    等主库 healthy 后单独启动：docker compose up -d mysql-slave；
  2. 从库首次初始化会从主库 mysqldump 全量快照（11 个业务库），耗时取决于机器性能；
  3. 从库初始化失败时重建：docker compose rm -sf mysql-slave && docker volume rm docker_mysql-slave-data && docker compose up -d mysql-slave。

7.5 SkyWalking Agent 注入（deployment.yaml:49-55）

通过 initContainer 拷贝 agent 到共享卷，主容器挂载：

JAVA_OPTS 含 -javaagent:/opt/skywalking-agent/skywalking-agent.jar（deployment.yaml:290），实现无侵入链路追踪。

7.6 collab 为何用 StatefulSet（statefulset.yaml 注释）

协同服务 Netty WebSocket 维持有状态长连接，会话（光标、在线用户、OT 操作序列）存 Pod 本地内存。StatefulSet 提供：

  1. 稳定网络标识：Pod 名 collab-0/1/2，DNS 可解析，客户端重连路由到同一 Pod 恢复会话；
  2. 稳定持久存储：每 Pod 独立 PVC，会话快照不丢；
  3. 有序启停：启动 0→1→2，停止 2→1→0，避免同时重启致全部会话中断。

Gateway 通过一致性哈希按 docId 路由到固定 collab Pod。

7.7 HPA 自动伸缩（hpa.yaml）

伸缩公式：目标副本 = ceil(当前副本 × 当前CPU% / 目标CPU%)。前置条件：安装 Metrics Server。

8.2 WebSocket 反代核心（nginx.conf:151-176）

关键点：

  1. proxy_http_version 1.1：WebSocket 依赖 HTTP/1.1 Upgrade 机制；
  2. $connection_upgrade 映射表（nginx.conf:109-112）：$http_upgrade 为 websocket 时 Connection=upgrade，否则 close；
  3. proxy_read_timeout 3600s：默认 60s 会断空闲长连接，必须调大；
  4. proxy_buffering off：关闭缓冲确保消息实时推送；
  5. ip_hash（nginx.conf:97）：保证同一客户端连同一后端，利于会话保持。

8.3 限流配置（nginx.conf:65-69）

三层限流：API 100r/s、WS 建连 10r/s、单 IP 并发连接 100（API）/50（WS）。

九、调优参数清单

9.1 Tomcat 调优（application.yml:3-11）

参数 默认值 压测推荐 说明
server.tomcat.max-threads 200 200（峰值拐点） 最大工作线程
server.tomcat.min-spare-threads 20 20 最小空闲线程
server.tomcat.max-connections 10000 10000 NIO 接收队列上限
server.tomcat.accept-count 100 100 连接满后排队上限
server.tomcat.connection-timeout 20000 20000 连接超时 ms

调优结论（详见《Zeus-Doc 性能压测实战》第三节）：

  • max-threads=200 为最优，TPS 4650 达峰，错误率最低 0.02%；
  • max-threads=500 反而下降：上下文切换加剧，GC 频次翻倍；
  • HikariCP maximum-pool-size=50 = max-threads 的 1/4（IO 等待期间释放连接）。

另提供 deploy/tomcat-tuning.yml 含完整压测对比配置。

十、常见问题排查

10.1 启动与连接问题

问题 排查 解决
服务启动报 Connection refused 连不上 Nacos docker compose -f docker-compose.lite.yml ps nacos2 确认 healthy；curl http://localhost:8848/nacos/v1/console/health/readiness 等中间件就绪后再启服务
Nacos 连接超时 检查 8848/9848 端口 gRPC 端口 9848 必须开放（2.x 客户端）
无效的目标发行版: 17 检查 ~/.mavenrc JAVA_HOME 指向 JDK 17
ES 报 analyzer [ik_max_word] not found curl http://localhost:9200/_cat/plugins?v IK 插件未安装或版本不匹配，按 4.3 节重装
ShardingSphere 路由异常 sql-show: true（sharding.yml:112） 查看实际路由 SQL
Seata 分支未注册 检查 XID 是否透传 Feign 配置 Seata 拦截器透传 XID
Bean 循环依赖 allow-circular-references application.yml:20 开启，或重构消除

10.2 内存不足 / 容器全部 unhealthy

原因： 全量模式中间件估算占用 ~8.5GB，超过 Docker 3.84GB 分配上限，健康检查漂移属资源超载信号。

解决：

  1. 改用模式一（推荐）：bash deploy/scripts/start-lite.sh，中间件压到 ~2.8GB；
  2. 若确需全量：Docker Desktop → Settings → Resources 把内存上限从 3.84GB 调到 6GB+；
  3. 微服务 JVM 一律 -Xmx256m（start-lite.sh 已内置）；
  4. 容器标 unhealthy 但服务实际正常时，直接验证服务本身（docker exec zeus-mysql mysql -uroot -pzeus@2024 -e "SELECT 1"）。

10.6 优雅停机

应用关闭流程（ThreadPoolConfig.java:99-101, 121-126）：

  1. K8s 发送 SIGTERM（terminationGracePeriodSeconds: 30，gateway 60s）；
  2. Spring Boot 优雅停机，拒绝新请求；
  3. 线程池 waitForTasksToCompleteOnShutdown=true，等待队列任务完成（最多 30s）；
  4. Feign/Netty 连接关闭，Pod 退出。

若 30s 内未退出，K8s 发 SIGKILL 强制终止。gateway 设 60s 因需等长连接断开。
