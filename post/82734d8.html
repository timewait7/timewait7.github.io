Linux 基础与 Shell 编程

Posted on 2024-12-13 In 部署运维 Word count in article: 6.5k Reading time ≈ 23 mins.

1. Linux 是什么

Linux 最初只是一个开源的操作系统内核（Kernel）。我们日常所说的”Linux 系统”，指的是 Linux 内核 + GNU 工具集等周边软件组成的完整可用系统，这类组合统称为发行版（Distribution），如 Ubuntu、Debian、CentOS、RHEL 等。

发行版之间的主要区别：

  • 包管理器不同：Debian 系（Ubuntu/Debian）用 apt，RedHat 系（CentOS/RHEL/Fedora）用 yum/dnf，Arch 系用 pacman。命令名不同，但理念一致——装包、卸包、更新、搜索
  • 预装软件和发布节奏不同（有的求稳、有的求新）

为什么服务器几乎都是 Linux：

  • 开源免费，没有授权费
  • 稳定：可以不重启连续运行数月甚至数年
  • 轻量：不需要图形界面，低配机器也能跑
  • 远程友好：SSH 登录即用，天然适合无头（headless）管理
  • 生态垄断：Nginx、MySQL、Docker、K8s 等服务端软件都优先支持 Linux

2. 文件系统

目录树

Linux 中”一切皆文件”，所有文件从根目录 / 开始，挂在一棵目录树上：

常用目录速记：

目录 作用
/etc 系统和应用程序的配置文件
/home 用户主目录（如 /home/alice）
/usr 应用程序和库；/usr/local 是源码安装软件的默认位置
/var 动态数据：日志、缓存、邮件
/tmp 临时文件
/proc 虚拟文件系统，反映内核和进程的实时信息
/dev 设备文件

绝对路径与相对路径

  • 绝对路径：从 / 开始写，如 /etc/nginx/nginx.conf，在任何目录下都有效
  • 相对路径：相对当前目录（pwd 可查看），如 ../conf/nginx.conf；. 表示当前目录，.. 表示上一级

inode 与链接

一个文件在磁盘上由两部分组成：

  • inode：元数据（大小、属主、权限、时间戳、数据块指针），每个 inode 有唯一编号
  • 数据块：文件的实际内容

文件名只是目录里的一条记录，指向某个 inode。由此引出两种链接：

  • 硬链接：多个文件名指向同一个 inode，删除一个名字后其他名字仍能访问文件。不能跨文件系统，不能链接目录
  • 软链接（符号链接）：一个独立的小文件，内容是指向目标的路径。目标被删，软链接就失效

日常最常用的是软链接，例如把编译安装的程序挂到 PATH 里：

文件属性

ls -l 输出的第一列就是文件的属性：

  • 第 1 个字符是类型：[d] 目录、[-] 文件、[l] 链接、[b] 块设备、[c] 字符设备
  • 后面 9 个字符分三组：所有者（u）、所属组（g）、其他人（o），每组按顺序是 r（读）、w（写）、x（执行）

3. 文件操作

按使用场景记命令，比背命令表快得多。

创建与移动

  • 想建多层目录：mkdir -p a/b/c（-p 递归创建，一路建到底）
  • 想建空文件，或更新已有文件的时间戳：touch file
  • 想移动或重命名：mv old new（重命名本质就是 mv）；mv -i 覆盖前询问
  • 想复制：cp -r dir1 dir2 递归复制目录；cp -a dir1 dir2 归档复制，保留权限、时间等元数据，常用作备份；cp -u 只在源文件更新时复制
  • 想知道自己在哪：pwd；想返回上次所在的目录：cd -
  • 查看目录内容：ls -l 详细信息；ls -a 含隐藏文件；ls -t 按时间排序（-r 倒序）

⚠️ 删除：rm file 删文件，删目录要加 -r。rm -rf 是”递归强制删除”，不询问直接删光且无法恢复——这是 Linux 上最著名的危险命令，回车前再检查一遍路径。

查看文件内容

  • 文件不大，整体看：cat file；要行号：cat -n file
  • 文件很长，只看开头或结尾：head -n 5 file、tail -n 5 file（-n 可省略写作 head -5）
  • 实时跟踪日志：tail -f app.log——日志不断追加，终端跟着刷新，排查线上问题首选；Ctrl+C 退出
  • 长文件翻页阅读：less file（支持上下翻页、/ 搜索、q 退出；vi 的翻页键都适用）
  • 清空一个文件但保留文件本身：cat /dev/null > file（日志文件常用，比”删掉重建”更安全）
  • 统计行数/词数/字节数：wc file（输出三个数：行、词、字节；只看行数用 wc -l）
  • 排序：sort file（-r 逆序；-n 按数值而不是字典序，排数字时必加）

搜索

  • 在文件内容里搜：grep "error" app.log
    • grep -n 带行号，方便定位；grep -i 忽略大小写
    • grep -r "TODO" src/ 递归搜索整个目录
    • grep -E "a|b" 用扩展正则；grep -C 5 显示匹配行前后各 5 行（-A 只往后、-B 只往前）
    • 详细用法见《grep、sed、awk》专题
  • 按文件名找文件：find /var/log -name "*.log"；-iname 忽略大小写；-type f 只看文件；-maxdepth 2 限制搜索深度（找不到时先想想是不是搜得太深太慢）
  • 快速全盘搜文件名：locate file 用预建索引，秒出结果，但索引非实时（新文件搜不到，需 updatedb 刷新）。记住：find 实时精确，locate 快但可能滞后
  • 想知道某命令装在哪个路径：which python（只查 PATH）；whereis python（连手册页、源码位置一起给出，whereis -b 只看二进制）

编辑与处理

  • sed 按行流式处理：sed -i 's/old/new/g' file 原地把文件里所有 old 替换成 new。⚠️ -i 直接改写文件，动手前先备份（cp file file.bak 或 sed -i.bak）
  • awk 按列处理：awk '{print $1}' file 打印每行第一列；awk -F: '{print $1}' /etc/passwd 以冒号分隔取第一列
  • 详细用法见《grep、sed、awk》专题

打包与压缩

场景 命令
打包并压缩 tar -czvf archive.tar.gz dir/（c 创建、z gzip、v 显示过程、f 指定文件名）
解压 tar -xzvf archive.tar.gz（x 解压；-C /target 解到指定目录）
只看压缩包里有什么 tar -tzvf archive.tar.gz
zip 格式 unzip file.zip；zip -r out.zip dir/

4. 权限管理

权限模型：每个文件有三个角色——所有者（u）、所属组（g）、其他人（o），每个角色拥有 r（读）、w（写）、x（执行）三种权限。

chmod 两种写法

  • 数字写法：r=4、w=2、x=1，三者相加。chmod 755 file = 所有者 rwx（7），组和其他 r-x（5）。数字就是该角色权限的”和”
  • 符号写法：chmod u+x file 给所有者加执行；chmod g-w file 去掉组的写；chmod a+r file 给所有人加读
  • 递归：chmod -R（对整个目录树生效，用前想清楚）

⚠️ chmod 777：所有人可读可写可执行，意味着任何用户都能改你的文件，服务器上几乎永远不该用。想让多用户协作，用组权限（chgrp + chmod g+rw）而不是 777。

属主与属组

  • 改属主/属组：chown user:group file（chown -R 递归）
  • 查看自己是谁：whoami；id 看 uid、gid、所属组

特殊权限位

  • SUID（chmod u+s，属性位显示为 s）：执行该程序时以属主身份运行，如 /usr/bin/passwd——所以普通用户也能改自己的密码
  • SGID（chmod g+s）：目录下新建的文件自动继承目录的属组，适合团队共享目录
  • Sticky bit（chmod +t，如 /tmp 上的 t）：目录里只有文件所有者（或 root）能删除文件

umask

新文件默认权限的”屏蔽值”。默认 022 意味着：新建文件 644，新建目录 755。umask 命令可查看和修改。

5. 进程管理

程序是磁盘上的静态文件，进程是运行中的实例，每个进程有唯一的 PID。启动一个程序时，bash 会 fork 出一个子进程；如果父进程先退出，子进程就变成孤儿，由 PID 1（systemd/init）收养——这就是父子进程关系。

  • 想快速看某个进程在不在、吃多少资源：ps -aux（a 所有用户、u 详细信息含 %CPU/%MEM、x 含后台进程）

  • 想看完整命令行和父进程：ps -ef（含 PPID）；进程树用 ps -ef --forest 或 pstree

  • 实时监控 CPU/内存占用：top——按 P 按 CPU 排序，按 M 按内存排序，q 退出。排查”哪个进程把 CPU 打满了”用它
  • 按名字找进程：pgrep nginx；或 ps -ef | grep nginx（记得排除 grep 自己，grep -v grep）
  • 杀掉进程：kill 1234 默认发 SIGTERM，让进程自己收尾（先给它机会）；⚠️ kill -9 1234 发 SIGKILL 强制击杀，进程没机会清理资源，是最后手段。kill -9 都杀不掉说明进程卡在内核态（如 D 状态磁盘 IO）
  • 进程随终端关闭而消失，想让它继续跑：nohup ./app > app.log 2>&1 &——nohup 忽略挂断信号，& 放后台，日志重定向到文件。启动服务跑后台全靠这一条
  • 后台任务管理：jobs 查看后台任务，fg 调回前台，Ctrl+Z 挂起，bg 转为后台运行

6. 网络与系统监控

网络排查

  • 想测网络通不通、延迟多少：ping -c 3 baidu.com（-c 限制发包次数，否则会一直 ping 下去）
  • 想看本机 IP：ip addr（旧命令 ifconfig 已逐步淘汰，新系统统一用 ip）
  • **排查”我的服务起没起来””这个端口被谁占了”**：ss -tulnp——-t TCP、-u UDP、-l 只看监听、-n 数字显示端口、-p 显示进程。ss 是 netstat 的现代替代，参数几乎通用，优先用 ss（netstat -tuln 同样可用）
  • HTTP/API 调试：curl，日常三招记住即可：
    • 只看响应头、检查状态码：curl -I https://example.com
    • 下载文件（保留原文件名）：curl -O http://example.com/file.zip
    • 测 POST 接口：curl -X POST -H "Content-Type: application/json" -d '{"k":"v"}' https://api.example.com
    • 常用选项：-s 静默（脚本里用）、-L 跟随重定向、-i 输出含响应头、-u user:pass Basic 认证
  • 大文件/批量下载：wget——-c 断点续传（大文件必备）、-O name 重命名、--limit-rate=1m 限速、-b 后台下载

系统监控

  • 磁盘还剩多少：df -h（-h 人类可读单位）
  • 哪个目录最占空间：du -sh /var/log（-s 只要总量）；找出大头：du -h --max-depth=1 | sort -hr
  • 内存还剩多少：free -h
  • 系统运行多久、负载多高：uptime
  • 管理服务（systemd）一句话：systemctl status/start/stop/restart/enable nginx——查状态、启动、停止、重启、开机自启，一套词表走天下

其他日常命令

  • history：history -5 看最近 5 条；!! 重跑上一条；!man 重跑最近一条以 man 开头的命令；history | grep xxx 翻历史
  • alias：alias ll='ls -l' 当前 shell 生效；要永久生效，写入 ~/.bashrc 后 source ~/.bashrc；unalias ll 删除
  • echo：echo -n "text" 输出不换行；echo $? 看上一条命令的退出码（0 成功，非 0 失败）——脚本调试第一手段
  • set：不带参数显示当前所有环境变量

7. Shell 编程

脚本骨架

变量

  • 定义 name=alice；引用 $name 或 ${name}；拼接 "Hello ${name}!"
  • 环境变量：$PATH、$HOME 等；export VAR=value 导出给子进程
  • 命令替换：today=$(date +%y%m%d) 把 date 的输出赋给变量（反引号 `date` 等价，推荐 $()）
  • 算术运算：$((3 * 5))；((x = x + 1)) 可用于赋值
  • 脚本参数：$1、$2 位置参数，$# 参数个数，$0 脚本名，$? 上一条命令退出码
  • 特殊技巧：IFS=$'\n' 把字段分隔符改为换行，for 遍历带空格的行时很有用

条件判断

  • 数值比较：[ n1 -gt n2 ]——-gt 大于、-lt 小于、-eq 等于、-ge 大于等于、-le 小于等于、-ne 不等于
  • 字符串比较：[ "$str" = "abc" ] 相同、!= 不同、-z "$str" 为空、-n "$str" 非空（比较时变量加引号，防空值报错）
  • 文件判断：[ -f file ] 是普通文件、[ -d dir ] 是目录、[ -e path ] 存在、[ -s file ] 非空、[ -w file ] 可写、[ -x file ] 可执行、[ file1 -nt file2 ] file1 比 file2 新
  • [[ ]] 是 bash 的扩展写法：支持 &&、|| 和 =~ 正则匹配，日常写 bash 脚本推荐优先用 [[ ]]（注意它只存在于 bash，sh 下没有）

循环

函数

常见陷阱

  1. 赋值等号两边不能有空格：name = "alice" 会被解析成运行 name 命令
  2. 变量引用不加大引号：值含空格或为空时命令会被拆散，[ "$str" = "abc" ] 而不是 [ $str = abc ]
  3. [ ] 内部各项必须用空格隔开：[ "$a" -eq 1] 会报错（1] 粘连）
  4. 字符串比较用 =，数值比较用 -eq，不能混用
  5. 空格敏感的还有 [ ] 和 then：if [ x ]; then 与分成两行等价
  6. 脚本执行权限：bash script.sh 不需要 x 权限；./script.sh 需要 chmod +x 且 shebang 正确
  7. 调试脚本：bash -x script.sh 逐行打印执行过程；bash -n script.sh 只查语法错误

8. 性能分析工具

服务器变慢了，先回答三个问题：是 CPU 不够、内存不足，还是磁盘太慢？ 三个工具各管一问：top 看 CPU、vmstat 看内存与调度、iostat 看磁盘。

8.1 top：CPU 与进程视图

top 输出的第一行就藏着两个关键信息：系统运行时长和 load average：

  • load average 三个值：1 分钟、5 分钟、15 分钟的平均活跃进程数（正在运行 + 不可中断睡眠 D 状态的进程）。判断标准：长期大于 CPU 核心数就是过载（nproc 看核心数；单核 1.0 是满）。三个值对比看趋势：15 分钟低、1 分钟高 → 刚刚涌入的负载；反之 → 负载正在回落。注意 load 高不一定是 CPU 忙——D 状态进程也在数里，所以 load 高还要用下面的字段区分。
  • CPU 占比字段：us 用户态、sy 内核态、wa IO 等待、st 被虚拟机偷走的时间。us 高 → 业务代码在算；sy 高 → 系统调用/锁/内核开销大；**wa 高 → 磁盘是瓶颈**；st 高 → 云主机被同宿主机邻居挤占。
  • 进程状态：R 运行、S 睡眠（可中断）、**D 不可中断睡眠**（在等磁盘 IO，kill -9 也杀不掉，只能等 IO 完成或重启）、Z 僵尸（父进程没回收）、T 停止。

交互快捷键：P 按 CPU 排序、M 按内存排序、1 展开每个核、c 显示完整命令行、H 切到线程视图（查哪个线程吃 CPU）、q 退出。

8.2 vmstat：内存与调度视图

关键字段与判断：

字段 含义 怎么判断
r 运行队列长度（就绪等待 CPU 的进程数） 长期 > CPU 核心数 → CPU 不够
b 阻塞进程数（主要在等 IO） 持续非 0 → IO 或锁等待
swpd 已用交换分区大小 长期非 0 → 内存吃紧过的信号
si / so 每秒从磁盘换入/换出内存的页数 持续活跃 → 物理内存不足，系统在内存与磁盘间来回倒数据，性能骤降
us / sy / wa CPU 分布（与 top 一致） wa 高 → IO 问题

判断内存是否充足的第一现场就是 si/so：物理内存够用就不该有换页。看到 si/so 持续非 0，配合 free -h 确认内存确实不够，再决定加内存、调 JVM 堆或关掉大页缓存。

8.3 iostat：磁盘视图

关键字段：

  • r/s、w/s：每秒读写次数（IOPS）；
  • rkB/s、wkB/s：每秒读写吞吐；
  • await：单次 IO 从发出到完成的平均耗时（毫秒），高了说明磁盘服务不过来（机械盘参考 ~10ms 内，SSD 应 < 2ms）；
  • %util：设备忙碌百分比，长期接近 100% → 磁盘是瓶颈。

注意 %util 高与 await 高的组合才有意义：%util 100% + await 高 → 磁盘真满了；%util 不高但 await 高 → 队列在别的层（如 RAID 卡、网络盘）。

8.4 三者联动：一次变慢的完整定位

三个工具配合，按下面的决策树走一遍就能定位瓶颈在哪一层：

瓶颈 特征组合 处理方向
CPU load 高 + r 高 + us/sy 高 优化代码/加 CPU/降并发
内存 si/so 活跃 + swpd 增长 加内存/调缓存与堆
IO wa 高 + b 高 + %util≈100% 换 SSD/加盘/优化 SQL（顺序读、减少随机写）

9.1 strace：跟踪系统调用

实战示例：应用启动时报”找不到配置文件”，用 strace -f -e trace=file ./app 2>&1 | grep -v ENOENT 可以完整看到它依次尝试打开了哪些路径——路径找错了还是权限不够，一目了然。跟踪网络时 -e trace=network 是日常最高频的组合。

9.2 lsof：文件与端口

lsof（list open files）列出进程打开的文件（Linux 下一切皆文件：普通文件、socket、管道）：

lsof -i :8080 的输出（COMMAND PID USER FD TYPE DEVICE SIZE NODE NAME）里 java 12345 root 21u IPv4 ... TCP *:8080 (LISTEN) —— 拿到 PID 和进程名就是下一步行动的依据。文件句柄泄漏的排查套路：连续采样 ls /proc/<PID>/fd | wc -l，数量只涨不跌 → 代码里有打开未关闭的句柄（连接、文件流），对照 ulimit -n（默认 1024/65535）看是否逼近上限。
