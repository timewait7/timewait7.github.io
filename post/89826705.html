Docker 容器实战

Posted on 2024-12-16 In 部署运维 Word count in article: 11k Reading time ≈ 39 mins.

1. Docker 解决什么问题

“在我机器上能跑啊？”——开发环境装好了、测试也通过了，换一台机器（同事电脑、测试服务器、生产服务器）就各种报错：JDK 版本不对、依赖缺失、系统库没有、配置文件忘改……环境差异是软件交付路上最常见的坑。

Docker 的解法是：把应用和它的完整运行环境（代码、运行时、依赖、配置、启动脚本）一起打包成一个镜像（Image）。镜像是不可变的、自包含的，在任何装了 Docker 的机器上，都能以完全一致的方式运行——这就是 一次构建，处处运行（Build Once, Run Anywhere）。

1.1 容器 vs 虚拟机

和虚拟机相比，Docker 共享宿主机内核、以进程级隔离运行。

对比 Docker 容器 虚拟机
隔离粒度 进程级（共享内核） 整机级（完整操作系统）
启动速度 秒级 分钟级
镜像/磁盘占用 几十 MB ~ 几百 MB 几个 GB 起步
单机密度 轻松几十上百个 通常个位数
隔离强度 较弱 更强
运行前提 Linux 内核 可运行完整 OS
典型技术 namespace、cgroups、UnionFS Hypervisor、Guest OS 
flowchart LR
    subgraph VM["虚拟机方案"]
        App1[App] --> GuestOS1[Guest OS]
        App2[App] --> GuestOS2[Guest OS]
        GuestOS1 --> Hypervisor
        GuestOS2 --> Hypervisor
        Hypervisor --> HostOS1[Host OS]
        HostOS1 --> Hardware1[硬件]
    end

    subgraph Docker["Docker 方案"]
        App3[App] --> Runtime3[Runtime/依赖]
        App4[App] --> Runtime4[Runtime/依赖]
        Runtime3 --> Engine[Docker Engine]
        Runtime4 --> Engine
        Engine --> HostOS2[Host OS]
        HostOS2 --> Hardware2[硬件]
    end

虚拟机每个都是完整操作系统，隔离更强但也更重；容器共享内核，更轻更快，但必须在 Linux 上运行（macOS/Windows 通过虚拟机跑 Linux 内核间接运行），且隔离强度弱于虚拟机——运行不可信代码等安全要求极高的场景仍需虚拟机或沙箱。

1.2 Docker 的典型价值

  • 环境一致性：开发、测试、生产使用同一镜像。
  • 交付标准化：镜像就是交付物，不再靠文档装环境。
  • 资源利用率高：一台机器可跑多个容器。
  • 弹性与编排：配合 Compose、Swarm、K8s 快速扩缩容。
  • CI/CD 友好：构建、测试、推送、部署全链路标准化。
  • 微服务基础设施：每个服务独立镜像、独立发布。

2. Docker 核心原理与架构

2.1 Docker 整体架构

flowchart LR
    Client[Docker Client<br/>docker CLI] -->|REST API| Daemon[Docker Daemon<br/>dockerd]
    Daemon --> Images[镜像 Images]
    Daemon --> Containers[容器 Containers]
    Daemon --> Networks[网络 Networks]
    Daemon --> Volumes[数据卷 Volumes]
    Daemon -->|pull/push| Registry[Registry<br/>Docker Hub / Harbor]
    Daemon --> Containerd[containerd]
    Containerd --> Runc[runc]
    Runc --> Kernel[Linux Kernel<br/>namespace/cgroups]

三个核心角色：

  • Docker daemon（守护进程）：运行在宿主机上，负责管理镜像、容器、网络、数据卷。
  • Docker client（客户端）：我们敲的 docker 命令，本质是把指令发给 daemon 执行，可以连本地或远程 daemon。
  • Registry（镜像仓库）：存放、分发镜像的地方，默认 Docker Hub，企业内部常用 Harbor。

补充：

  • containerd 是更底层的容器运行时，负责容器生命周期管理。
  • runc 是 OCI 运行时，真正调用 Linux 内核创建容器。
  • K8s 通过 CRI 接入 containerd、CRI-O 等，不再强依赖 Docker Engine。

2.2 Linux 内核基础

Docker 不是“轻量虚拟机”，而是利用 Linux 内核能力实现的进程隔离：

技术 作用
namespace 隔离视图：PID、网络、挂载、UTS、IPC、User
cgroups 限制资源：CPU、内存、IO、进程数
UnionFS 联合文件系统，实现镜像分层与写时复制
chroot/pivot_root 改变根文件系统
capabilities 细粒度权限控制
seccomp 限制系统调用
AppArmor/SELinux 强制访问控制

常见 namespace：

  • PID：容器内看不到宿主机其他进程。
  • NET：独立网络栈、网卡、端口。
  • MNT：独立挂载点。
  • UTS：独立 hostname。
  • IPC：独立进程间通信。
  • USER：用户和用户组隔离。

2.3 镜像分层与写时复制

镜像不是一个大文件，而是一层层只读层堆叠而成，底层机制叫联合文件系统 UnionFS。

flowchart TB
    ContainerLayer["容器可写层（Container Layer）"]
    ImageLayer3["镜像层 3：COPY app.jar"]
    ImageLayer2["镜像层 2：RUN 安装依赖"]
    ImageLayer1["镜像层 1：FROM openjdk:11"]
    Base["基础镜像层"]

    ContainerLayer --> ImageLayer3
    ImageLayer3 --> ImageLayer2
    ImageLayer2 --> ImageLayer1
    ImageLayer1 --> Base
  • 镜像里的每一层，都对应 Dockerfile 里的一条指令，如 RUN、COPY。
  • 容器启动时，Docker 在镜像层之上再加一层可写层（容器层）。
  • 容器层不会修改任何镜像层：修改文件时先复制到容器层再改，这就是写时复制（Copy-on-Write）。
  • 容器一删，可写层消失，镜像完好无损。

好处：

  1. 省空间：多个镜像共用基础层。
  2. 构建、传输快：层可复用，构建命中缓存，推送只传变化层。
  3. 升级轻量：应用升级往往只新增一层。

2.4 容器生命周期

stateDiagram-v2
    [*] --> Created: docker create
    Created --> Running: docker start
    Running --> Paused: docker pause
    Paused --> Running: docker unpause
    Running --> Stopped: docker stop
    Stopped --> Running: docker start
    Stopped --> [*]: docker rm
    Running --> [*]: docker rm -f
    Running --> Dead: OOM / crash
    Dead --> [*]: docker rm

4. 镜像与容器

4.1 镜像 = 类，容器 = 实例

概念 类比 说明
镜像（Image） 类 只读的静态模板，包含应用和完整运行环境
容器（Container） 实例 镜像运行起来的进程，有独立可写文件层
仓库（Registry） 代码仓库 存放和分发镜像

同一个镜像可以启动任意多个容器，互不影响；容器删了重建，镜像毫发无损。容器天然是临时、无状态的，需要持久保存的数据必须放到数据卷里。

常见状态：

  • created：已创建未启动。

  • exited：已退出。
  • restarting：重启中。
  • dead：异常死掉。

5. 常用命令

命令很多，不用背。按一个容器从生到死的流程来记：拉取镜像 → 运行容器 → 查看状态 → 排查问题 → 停止删除。

    B --> C[docker ps]
    C --> D[docker logs / exec / inspect]
    D --> E[docker stop]

5.1 镜像操作

场景 命令 说明
搜索镜像 docker search nginx 在 Docker Hub 上搜索
拉取镜像 docker pull nginx 不写版本默认拉 latest；docker pull mysql:5.7 拉指定版本
查看本地镜像 docker images -q 只显示镜像 ID
删除镜像 docker rmi nginx 参数是镜像名或 ID；docker rmi $(docker images -q) 批量删除
导出镜像 docker save -o nginx.tar nginx:1.25 生成 tar 包，含全部历史层
导入镜像 docker load -i nginx.tar 与 save 成对使用
查看镜像历史 docker history nginx:1.25 查看每层来源
查看镜像详情 docker inspect nginx:1.25 输出 JSON

docker save / docker load 的典型场景是离线环境：内网机器连不上外网，就在有网机器上 pull 好镜像，save 成 tar 包拷进去，再 load 还原。

6. 数据卷与持久化

6.1 为什么需要数据卷

  1. 容器是临时的：删除容器，可写层数据一并消失。MySQL 数据、应用日志必须持久保存。
  2. 容器内改文件不方便：改 nginx 配置、换静态页面都要 exec 进容器。
  3. 多容器需要共享文件：日志采集、静态资源等。
flowchart LR
    subgraph Host["宿主机"]
        HV["/var/lib/docker/volumes/html/_data"]
        HB["/root/mysql/data"]
    end

    subgraph Container["容器"]
        CV["/usr/share/nginx/html"]
        CB["/var/lib/mysql"]
    end

    HV <--> CV
    HB <--> CB

6.2 三种挂载方式

方式 写法 特点 适用场景
命名卷（Volume） -v 卷名:/容器目录 由 Docker 管理，数据在 /var/lib/docker/volumes/卷名/_data 持久化核心数据，如数据库数据目录
绑定挂载（Bind Mount） -v /宿主机绝对路径:/容器目录 直接映射宿主机目录，宿主机可直接改文件 配置文件、源码、nginx 静态页面
临时挂载（tmpfs） --tmpfs /容器目录 存在内存里，不落盘，容器重启即消失 临时敏感数据

7.3 ARG 与 ENV 区别

  • ARG：构建参数，docker build --build-arg 传入，构建后不保留在运行环境。
  • ENV：环境变量，构建和运行都生效，会写入镜像配置。

7.4 CMD 与 ENTRYPOINT 的区别

  • CMD：默认命令。docker run 镜像 参数 会把 CMD 整体替换掉。
  • ENTRYPOINT：入口命令，固定不可被普通参数覆盖，只有 --entrypoint 才能改。

8. Docker 网络

8.1 Docker 网络模式

模式 说明 使用场景
bridge（默认） 容器接入虚拟网桥 docker0，每个容器有独立 IP，容器间可互通；对外需 -p 映射 单机绝大多数场景
host 容器与宿主机共享网络栈，直接用宿主机 IP 和端口 网络性能要求高、端口固定
none 容器完全没有网络 纯计算任务、高安全要求
overlay 跨主机容器组网 多机集群，Swarm / K8s
macvlan 给容器分配 MAC 地址，使其像物理机一样接入网络 特殊网络需求

8.3 端口映射

flowchart LR
    User[用户] -->|宿主机:80| HostPort[宿主机端口 80]
    HostPort -->|docker-proxy| ContainerPort[容器端口 80]
    ContainerPort --> Nginx[nginx 进程]
  • -p 宿主机端口:容器端口：如 docker run -d -p 80:80 nginx。
  • 端口冲突：宿主机端口全局唯一，多个容器不能同时占用同一个宿主机端口。
  • -P：把镜像 EXPOSE 声明的端口自动映射到宿主机随机高位端口。
  • host 模式直接用宿主机端口，不需要也不能做端口映射。
  • 默认 bridge 下，容器端口只有映射后才能被宿主机外部访问；同一网络内容器之间直接用容器端口互访，无需映射。

8.4 容器访问外网与 DNS

  • 默认 bridge 通过 NAT 访问外网。
  • 自定义网络内置 DNS，服务名解析为容器 IP。
  • 容器内 DNS 配置来自宿主机或 --dns。
  • 排查：docker exec -it app ping mysql、nslookup mysql、cat /etc/resolv.conf。

12. Harbor 私有仓库

12.1 Harbor 是什么

Docker Hub 拉取慢、私有镜像不想放公网、团队需要权限管理和安全扫描——Harbor 是开源企业级镜像仓库，现为 CNCF 项目。

能力：

  • 项目管理与权限：项目管理员 / 开发者 / 访客。
  • 镜像漏洞扫描：内置 Trivy。
  • 镜像复制：跨机房、跨地域同步。
  • 审计与配额：操作日志、项目镜像数量/大小配额。

12.2 Harbor 组件架构

flowchart TB
    Client[docker login / pull / push] -->|443| Nginx[Nginx 代理]
    Nginx --> Core[Core 服务 API+WebUI]
    Nginx --> Registry[Registry 镜像存储]
    Core --> DB[(PostgreSQL)]
    Core --> Redis[(Redis)]
    Core --> Jobservice[Jobservice]
    Jobservice --> Trivy[Trivy 扫描]
    Registry --> DataVolume[data_volume]
组件 职责
Nginx 代理 统一入口，443 终结 TLS，按路径路由
Core 服务 业务 API + Web UI 后端
Registry 镜像本体存储
Database（PostgreSQL） 元数据：项目、用户、角色、扫描报告
Redis 缓存与异步任务队列
Jobservice 复制、垃圾回收、扫描等后台任务
Trivy 镜像漏洞扫描器

14. 面试高频问答

14.1 基础概念

  1. Docker 是什么？
    容器化平台，把应用和运行环境打包成镜像，实现一次构建处处运行。

  2. 容器和虚拟机区别？
    容器共享宿主机内核，进程级隔离，轻量快速；虚拟机有完整 Guest OS，隔离强但重。

  3. Docker 架构？
    Client、Daemon、Registry；底层 containerd、runc、Linux 内核。

  4. 镜像和容器区别？
    镜像是只读模板，容器是镜像运行实例，有可写层。

  5. 容器为什么删了就没了？
    数据写在可写层，随容器删除而消失；持久化要用数据卷。

  6. 什么是镜像分层？
    每条 Dockerfile 指令生成一层，层可复用，节省空间和传输。

  7. 什么是写时复制？
    修改文件时先复制到可写层再改，镜像层不变。

  8. namespace 和 cgroups？
    namespace 隔离视图，cgroups 限制资源。

  9. Docker 和 containerd 关系？
    Docker 是完整平台，containerd 是底层运行时，runc 真正创建容器。

  10. Docker 和 K8s 关系？
    Docker 构建运行单容器，K8s 编排集群；K8s 通过 CRI 接 containerd 等。

14.2 命令与操作

  1. 如何查看容器日志？ docker logs -f 容器
  2. 如何进入容器？ docker exec -it 容器 bash
  3. 如何查看容器 IP？ docker inspect -f '{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}' 容器
  4. 如何复制文件？ docker cp
  5. 如何清理磁盘？ docker system prune -a
  6. 如何导出导入镜像？ docker save / docker load
  7. 如何查看镜像历史？ docker history
  8. 如何查看容器资源？ docker stats
  9. 如何查看容器进程？ docker top
  10. 如何查看端口映射？ docker port

14.3 Dockerfile

  1. CMD 和 ENTRYPOINT 区别？ CMD 可被覆盖，ENTRYPOINT 不可被普通参数覆盖。
  2. COPY 和 ADD 区别？ ADD 可解压 tar，COPY 更纯粹。
  3. ARG 和 ENV 区别？ ARG 构建参数，ENV 构建和运行都生效。
  4. 如何减小镜像？ 多阶段构建、Alpine、清理缓存、.dockerignore。
  5. 为什么推荐 exec 形式？ 信号能正确传给 PID 1。
  6. 如何非 root 运行？ USER 指令。
  7. 健康检查怎么做？ HEALTHCHECK。
  8. 多阶段构建好处？ 构建工具不进入最终镜像。
  9. 构建缓存如何命中？ 指令和文件不变则复用。
  10. 如何多架构构建？ docker buildx。

14.4 数据与网络

  1. Volume 和 bind mount 区别？ Volume 由 Docker 管理，bind 直接映射宿主机目录。
  2. 如何持久化 MySQL？ 挂载 /var/lib/mysql。
  3. 如何备份卷？ tar 容器。
  4. Docker 网络模式？ bridge、host、none、overlay、macvlan。
  5. 自定义网络好处？ 内置 DNS，容器名互访。
  6. 端口映射原理？ docker-proxy/iptables 转发。
  7. 容器间如何通信？ 同一网络用服务名。
  8. 容器无法访问外网？ 检查 NAT、ip_forward、DNS。
  9. overlay 用在哪？ 跨主机集群。
  10. host 模式特点？ 共享宿主机网络栈。

14.5 生产与排错

  1. 如何限制资源？ --cpus、--memory。
  2. OOM 怎么排查？ docker inspect、docker events。
  3. 日志打满磁盘？ 配置日志轮转。
  4. 端口冲突？ lsof -i 找进程。
  5. 僵尸容器？ --init 或 init: true。
  6. unhealthy？ 检查 healthcheck 命令和 start_period。
  7. 权限拒绝？ 设置 user 或调整目录权限。
  8. 拉取慢？ 镜像加速器。
  9. 容器时间不对？ TZ 或挂载 localtime。
  10. 如何优雅停止？ 处理 SIGTERM，exec 形式。

14.6 Compose、Harbor、监控

  1. Compose 作用？ 单机多容器声明式编排。
  2. depends_on 保证就绪吗？ 不，配合 healthcheck。
  3. Compose 和 K8s 区别？ 单机 vs 集群。
  4. Harbor 组件？ Nginx、Core、Registry、DB、Redis、Jobservice、Trivy。
  5. Harbor 如何扫描？ Trivy。
  6. 镜像复制？ 跨 Harbor 同步。
  7. GC 作用？ 清理未引用 blob。
  8. 监控用什么？ cAdvisor + Prometheus + Grafana。
  9. 日志驱动？ json-file、journald、fluentd 等。
  10. docker events 用途？ 审计和异常退出告警。

15. 最佳实践与速查

15.1 最佳实践

  • 使用 .env 文件：敏感信息和可变配置放入 .env，Compose 中引用。
  • 定期清理：无用镜像、容器和构建缓存会持续占用磁盘。
  • 备份数据卷：重要数据用数据卷持久化并定期备份。
  • 关注官方更新：及时升级 Docker，修复安全漏洞。
  • 镜像标签固定版本：生产不要使用 latest。
  • 非 root 运行：降低容器逃逸风险。
  • 配置日志轮转：避免磁盘被日志打满。
  • 健康检查：让编排系统知道服务是否真正就绪。
  • 资源限制：防止单个容器拖垮宿主机。
  • 镜像扫描：Harbor + Trivy 或 CI 中集成扫描。
  • 最小镜像：多阶段构建、Alpine、Distroless。
  • 不要把密钥打进镜像。
  • 一个容器一个进程。
  • 使用自定义网络。
  • 使用 Compose 管理本地多服务。
  • 生产考虑 K8s。
