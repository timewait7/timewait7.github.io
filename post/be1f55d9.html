对于 web 服务来说，大部分情况下，请求参数分为如下两种形式：

  • GET 请求，使用 @RequestParam 和 @PathVariable 传递参数
  • POST 和 PUT 请求，使用 @RequestBody 传递参数
GET 请求参数校验

GET 请求一般用 @RequestParam 或 @PathVariable 传参，需在 Controller 上加 @Validated 注解，并在接口参数加约束注解，自动参数校验才能生效。校验失败会抛出 javax.validation.ConstraintViolationException 异常。

POST/PUT 请求参数校验

POST 或 PUT 请求一般用 @RequestBody 传参，后端使用 DTO 对象接收参数，只需要在 DTO 对象前加上 @Valid 或 @Validated 注解就可以实现自动参数校验，校验失败会抛出 org.springframework.web.bind.MethodArgumentNotValidException 异常。

假设表里存在一条数据，type 列的值为 2，使用 JPA 查询这条数据时会报数组越界异常：

排查过程

从异常堆栈可以看到数组越界发生在枚举转换阶段，定位到 @Enumerated 注解上。查资料确认：@Enumerated 默认按枚举的 ordinal()（声明顺序的下标）存取数据库值。

排查过程

经查资料发现 JPA 在调用 save 方法保存对象时会将对象缓存在一级缓存中，如果保存之后立即查询该对象，会从缓存中获取数据，而不是从数据库中重新查询。而内存中的 dataObject 的 updatedAt 字段是 Date 类型，只有在真正保存到数据库中，才会序列化为时间戳类型。

根因

一级缓存（EntityManager 缓存）导致保存后立即查询不落库，拿到的是内存中的对象，而非数据库中的持久化数据。

jackson 序列化空指针异常

问题现象

使用 Jackson 序列化 Storage 对象时，如果 endpoint 为 null，会报空指针异常。

排查过程

顺着空指针堆栈定位到 getRegion 方法，怀疑是 Jackson 在序列化时调用了该方法。查资料确认：Jackson 会把以 get 开头、无参数的方法当作属性 getter，序列化时会遍历调用。

根因

getRegion() 被 Jackson 识别为属性 region 的 getter，序列化时会调用该方法；此时 endpoint 为 null，endpoint.split("\\.") 抛出空指针异常。

解法

修改方法名，让方法不再以 get 开头，如将 getRegion 改为 resolveRegion，Jackson 就不会把它当作属性 getter。
