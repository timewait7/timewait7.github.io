Git 原理与实践

Posted on 2024-11-28 In 开发工具 Word count in article: 6.2k Reading time ≈ 23 mins.

Git 常用命令：Reference

1. Git 的核心概念

1.1 快照 vs 差异

Git 保存的是快照而不是差异。每次提交时，Git 会记录所有文件当时的完整状态（未变化的文件直接复用已有的对象），而不是像 SVN/CVS 那样只记录”改了哪些行”。

快照式存储带来的好处：

  • 任意一次提交都可以独立检出，不需要从初始版本逐个应用差异；
  • 分支、切换、合并本质都是移动指针 + 复用对象，速度极快；
  • 内容寻址：每个文件内容都有唯一的校验和（SHA-1），内容相同则对象唯一。

1.2 三区模型

Git 的日常操作都发生在三个区域之间：

  • 工作区：你编辑文件的目录；
  • 暂存区：git add 把改动暂存到这里，相当于”准备提交的内容”；
  • 版本库：git commit 把暂存区内容固化成提交对象，HEAD 指向当前分支的最新提交。

三个区之间的流转命令：

命令 流转
git add <file> 工作区 → 暂存区
git commit -m "msg" 暂存区 → 版本库
git push 本地版本库 → 远程仓库
git pull（fetch + merge） 远程仓库 → 工作区
git restore --staged <file> 暂存区 → 工作区（取消暂存）
git restore <file> 版本库 → 工作区（放弃修改）

3. 分支管理

Git 分支本质上就是指向提交对象的可变指针（第 7 节有实操验证），因此创建、切换、删除分支都极其高效。

3.1 创建、切换与删除

命令 说明
git branch dev 创建分支
git checkout dev 切换分支
git checkout -b dev 创建并切换分支
git switch dev / git switch -c dev 切换 / 创建并切换分支（2.23+ 推荐，语义更清晰）
git checkout -b dev origin/dev 从远程分支创建分支
git checkout --track origin/dev 从远程分支创建分支
git branch -u origin/dev 设置本地分支跟踪远程分支
git branch -v 查看每一个分支的最后一次提交
git branch -vv 查看设置的所有跟踪分支
git branch --merged 查看已合并分支
git branch --no-merged 查看未合并分支
git branch -d dev 删除分支（已合并才能删）
git branch -D dev 强制删除分支
git push origin --delete dev 删除远程分支
git branch --unset-upstream 分支名 取消本地分支与远程分支的关联

3.2 merge：合并分支

fast-forward（快进合并）：当前分支指向的提交是被合并分支所指向的提交的直接上游时，git merge 只是简单地把当前分支指向被合并分支的提交，不产生新的合并提交。

三方合并（3-way merge）：两条分支各有分叉时，Git 基于”共同祖先 + 两个分支的最新提交”三方合并，产生一个有多个父提交的合并提交。

3.3 rebase：变基

3.4 merge vs rebase 选型

维度 merge rebase
历史形态 保留分叉与合并节点 线性，无合并节点
是否改写提交 否（追加合并提交） 是（提交被重写，哈希变化）
冲突处理 一次解决 每个提交逐个重放，可能多次解决
安全性 对已推送分支安全 绝不能对已推送的公共分支执行

最佳实践：rebase 只用于推送前整理自己的提交历史，并且只在从未推送至公共仓库的提交上执行；已推送分支的整合一律用 merge，多人协作时用 merge --no-ff 保留合并记录。

5. 撤销与回退

这是最容易混淆的一组命令，先记住一句话：

  • git reset：移动 HEAD 和分支的指针，改写历史，用于撤销本地未推送的提交；
  • git restore：操作文件，把工作区/暂存区的文件还原，不产生任何提交层面的影响；
  • git revert：追加一个反向提交，不改写历史，用于安全地撤销已推送的提交。

5.1 reset：回退提交

命令 说明
git reset --soft HEAD~ 回退到上一个提交，暂存区和工作目录不变
git reset [--mixed] HEAD~ 默认模式，回退到上一个提交，取消暂存，保留工作目录的修改
git reset --hard HEAD~ 回退到上一个提交，撤销工作目录的所有修改（慎用，会丢改动）

git reset 会同时移动 HEAD 和分支的指向，git checkout 只移动 HEAD。

5.2 restore：还原文件

命令 说明
git restore --staged <file>... 取消暂存
git restore <file>... 撤销修改（回到版本库状态）

5.3 revert：撤销已推送的提交

revert 适合”提交已经推送到远程、别人可能已基于它开发”的场景——它只是追加一个抵消操作，不会造成历史分歧。

5.4 三者对比

命令 作用对象 是否改写历史 典型场景
reset 提交（HEAD/分支指针） 改写（回退） 撤销本地未推送的提交
restore 文件（工作区/暂存区） 不涉及提交 放弃修改、取消暂存
revert 提交（生成反向提交） 不改写（追加） 撤销已推送的提交

执行 git commit 时，Git 做了三件事：

  1. 为每一个有文件变更的目录生成一个 tree 对象（记录目录下有哪些文件名、分别指向哪个 blob）；

7.3 git branch / git checkout：分支就是指针

Git 分支，本质上就是指向提交对象的可变指针。在 .git/refs/heads 目录下，每个分支都有一个对应文件，存储当前分支所指向的最新提交的校验和。创建分支就是新建一个分支文件写入校验和，删除分支就是删除分支文件——所以 Git 分支的创建和销毁都极其高效。
