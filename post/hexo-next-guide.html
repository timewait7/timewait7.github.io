Hexo + NexT 博客搭建全指南

按本指南逐步操作，你将得到一个与当前站点完全一致的博客：Hexo 静态站点 + NexT 主题（Gemini），包含四层导航菜单、分类导航页体系、菜单树面包屑、短链接（abbrlink）与站内搜索。全文只讲操作，照做即可。

1. 最终效果与目录结构

  • 四层点击式菜单：Docs → 五大分类 → 子分类 → 文章，左侧菜单逐层展开
  • 分类导航页：每个分类一张 page，组织学习路线与文章定位（不计入文章列表）
  • 菜单树面包屑：每个导航页标题下方自动显示「Docs / 上一级 / 当前页」的居中面包屑
  • 短链接：文章 URL 为 /post/6a6e612d.html 形式，不暴露中文文件名
  • 站内搜索：Ctrl+K / ⌘K 全局搜索

5.3 Mermaid 图表渲染

本站图表支持两种写法，渲染效果一致，推荐代码围栏（编辑器里可直接预览）：

方式 写法 渲染机制
代码围栏（推荐） ```mermaid 围栏 hexo-filter-mermaid-diagrams 插件把围栏转成 <pre class="mermaid">，由 scripts/mermaid-fences.js 按需加载 mermaid.js 渲染（本地 vendor，无 CDN）
主题标签 {% mermaid %} 标签 同一加载器兼容 <code class="mermaid"> 结构，两种格式统一渲染

5.3.1 方式一：代码围栏（推荐）

用 mermaid 代码围栏（三个反引号 + mermaid）包裹图表：

flowchart LR
  A[开始] --> B{判断}
  B -->|是| C[结果]
  B -->|否| A

渲染为一张可交互的流程图（放大、导出 SVG）。图表源码里的 <、& 会被构建期自动转义，可放心书写。

5.3.2 方式二：主题标签

用 {% mermaid %} 标签包裹（NexT 原生语法，老文章在用；两种方式按文章自由选择，互不影响）：

{% mermaid %}
flowchart LR
  A[开始] --> B{判断}
  B -->|是| C[结果]
  B -->|否| A
{% endmermaid %}

标签内容的转义与围栏方式相同。

5.3.3 常用图表类型

类型 语法关键字 典型场景
流程图 flowchart LR / flowchart TD 流程、逻辑分支
时序图 sequenceDiagram 接口调用、消息交互
状态图 stateDiagram-v2 状态机、生命周期
类图 classDiagram 类与关系
甘特图 gantt 计划排期

5.3.4 配置与依赖

位置 配置 作用
_config.yml mermaid.enable: true 插件开关：构建期把代码围栏转成 <pre class="mermaid">
scripts/mermaid-fences.js 无需配置 构建期转义 </&；页面按需加载 mermaid.js 渲染所有 .mermaid 元素（两种格式都认）
_config.next.yml mermaid.enable: false 主题内置加载器只识别标签结构（选择器 pre > .mermaid），与插件输出不兼容，保持关闭

注意：图内文字建议用英文（中文在部分 mermaid 版本渲染偶发换行错位）；图表源码里的 <、& 会被构建期自动转义，可放心书写。同一张图不要同时用两种方式各写一遍，否则页面会出现两份相同的图表。

6. 博客布局

本站的体系是「文章 + 导航页」双轨：

  • 文章（source/_posts/）：真实内容，计入文章列表，URL 为 /post/<短码>.html
  • 导航页（source/docs/、source/docs/nav/）：分类索引，layout: page，不计入文章列表，URL 等于物理路径（/docs/nav/java-nav.html）

6.2.1 菜单结构

6.2.2 相对路径规则

每个节点的配置值 = 从父节点页面出发，到目标页面的相对路径：

节点 父页面 目标页面 配置值
顶级 Docs 无 /docs/ /docs/（绝对路径）
第二层 /docs/ /docs/nav/xxx.html nav/xxx.html
第三层 /docs/nav/xxx.html 同目录的另一导航页 ../yyy-nav.html
分组落地页 /docs/ 组页面（如 /docs/nav/data-storage-nav.html） nav/data-storage-nav.html
叶子（文章） /docs/nav/xxx.html /post/xxx.html ../../../post/xxx.html

规则记忆法：第二层从 /docs/ 进入 nav/ 目录；导航页互跳用 ../；文章目录 /post/ 与 /docs/nav/ 互不相干，需向上三级（docs/nav/ → docs/ → 根）再进入 post/。

坑：分组节点必须指向独立页面，不能指向锚点，也不能指向子页路径。

  • 曾把分组 default 写成 ../backend-dev-nav.html#数据存储，希望省一张页面。结果菜单高亮逻辑（主题 utils.js 的 registerActiveMenuItem）用 location.pathname 做前缀匹配，而 pathname 不含 #hash——4 个指向同一页面不同锚点的链接会同时高亮，点击也不会跳新页面，只在原页面内滚动。每个分组必须是一张真实落地页，页面内容写学习路线与子主题入口（见 6.1.2 内容定位）。
  • 分组 default 也不能直接指向子页路径（如 ../java-nav.html）：menu_map 是扁平 Map（子页先注册、组后注册会覆盖同名 key），会破坏该子页的面包屑层级。

6.2.3 图标

菜单图标使用 FontAwesome：|| fa fa-xxx。分类用语义化图标（书、代码、数据库、服务等），文章统一 fa fa-file-code。
