Phase 3: 自定义 Starter

学习目标

实现 zeus-doc-starter-draft，深入理解 Spring Boot 自动装配机制。

核心知识点

  • @AutoConfiguration + @ConditionalOnProperty 条件装配
  • spring.factories → META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports（Spring Boot 3.x 方式）
  • @EnableDraft 开关注解
  • Redis 防抖自动保存（1s 延迟）

实现步骤

  1. DraftAutoConfiguration.java：

    • @AutoConfiguration 标注
    • @ConditionalOnProperty(prefix = "zeus.draft", name = "enabled", havingValue = "true")
    • 注册 DraftSaveService Bean

  2. DraftSaveService.java：

    • 接收文档内容，防抖 1s 后异步保存到 Redis
    • 使用 ScheduledExecutorService 延迟执行

  3. @EnableDraft.java：

    • @Import(DraftAutoConfiguration.class) 开关注解

  4. 自动装配注册文件：

    内容：com.zeus.draft.starter.autoconfigure.DraftAutoConfiguration

参考文件

  • zeus-doc-starter-draft/src/main/java/com/zeus/draft/starter/ 下 5 个文件

⚠️ 常见坑点

  • Spring Boot 3.x 不再用 spring.factories，改用 AutoConfiguration.imports
  • Starter 的 pom.xml 不要有 spring-boot-maven-plugin（Starter 是被引入的库，不是可执行应用）

验收标准

  • Starter 模块编译通过
  • 在 doc 服务引入后，@EnableDraft 可激活自动保存

Phase 4: 网关 Gateway

学习目标

实现 Spring Cloud Gateway 网关：路由转发 + JWT 全局鉴权 + Sentinel 限流。

核心知识点

  • Gateway 的 GlobalFilter 与 GatewayFilter 区别
  • 路由配置（spring.cloud.gateway.routes）
  • WebFlux 响应式编程（网关基于 Netty + WebFlux，非 Servlet）
  • Sentinel 网关限流规则

实现步骤

  1. AuthGlobalFilter.java：

    • 实现 GlobalFilter, Ordered
    • 从 Header 提取 JWT → 校验 → 注入 X-User-Id 到下游请求
    • 白名单路径（登录/注册）直接放行
    • order 设为 -100（最高优先级）

  2. GatewayConfig.java：路由规则（6 个服务路由）

  3. application.yml：

参考文件

  • zeus-doc-gateway/src/main/java/com/zeus/gateway/ 下 5 个文件

⚠️ 常见坑点

  • Gateway 基于 WebFlux，**不能引入 spring-boot-starter-web**（会冲突）
  • GlobalFilter 返回 Mono<Void>，不能用 blocking 操作
  • JWT 校验失败时返回 401，注意设置 exchange.getResponse().setStatusCode()

验收标准

  • 网关启动成功，路由到各服务
  • 无 Token 请求返回 401

Phase 5: 用户服务

学习目标

实现用户注册、登录、JWT Token 签发与刷新。

核心知识点

  • BCrypt 密码加密（面试：为什么不用 MD5？彩虹表攻击 + BCrypt 自带盐）
  • JWT 三段式结构（Header.Payload.Signature）
  • 防暴力破解（Redis 记录失败次数，5 次锁定 15 分钟）

实现步骤

  1. AuthService.java：

    • register(username, password) → BCrypt 加密 → 存 MySQL
    • login(username, password) → BCrypt 校验 → 签发 JWT
    • refreshToken(oldToken) → 校验 → 签发新 Token
    • 防暴力破解：Redis login_fail:{username} 计数

  2. AuthController.java：REST 接口

  3. UserEntity / UserMapper.java：MyBatis 数据层

  4. application.yml：数据源 + Nacos + Redis

参考文件

  • zeus-doc-service-user/src/main/java/com/zeus/user/ 下 11 个文件

验收标准

  • 注册 → 登录 → 获得 JWT Token
  • 错误密码 5 次后锁定

Phase 6: 文档服务核心（最大模块）

学习目标

这是项目的核心模块（47 个 Java 文件），覆盖最多面试考点。

分 10 个子步骤实现

6.1 文档 CRUD + MyBatis

实现：

  • DocController → DocService → DocMapper
  • 软删除（status: NORMAL → TRASH → DELETED）
  • SqlCostInterceptor.java — MyBatis 拦截器监控慢 SQL

面试要点：MyBatis 四大核心对象（Executor/StatementHandler/ParameterHandler/ResultSetHandler），@Intercepts 拦截 Executor.query/update。

参考：controller/, service/DocService.java, mapper/, plugin/SqlCostInterceptor.java

6.2 三级缓存（面试核心）

实现 cache/CacheService.java：

关键类：

  • CacheService.java — 三级缓存编排
  • BloomFilterUtil（在 common 中）— 启动时预热所有 docId

面试要点：缓存三兄弟（雪崩/穿透/击穿）的解决方案，随机过期防雪崩、布隆过滤器防穿透、互斥锁防击穿。

6.3 线程池隔离

实现 threadpool/ThreadPoolConfig.java：

  • 4 个隔离线程池：doc-executor（核心写）、audit-executor（日志）、search-sync-executor（ES 同步）、export-executor（导出）
  • 每个池不同拒绝策略：AbortPolicy / CallerRunsPolicy / DiscardOldestPolicy
  • TtlExecutorUtil.wrap() 包装为 TTL 线程池，传递 UserContext

⚠️ 坑点：RejectedExecutionHandler 是 java.util.concurrent 的顶层接口，不是 ThreadPoolExecutor 的嵌套类。

6.4 CompletableFuture 并行聚合

实现 service/DocDetailService.java：

  • 并行查 3 个数据源：元数据(DB) + 正文(缓存) + 权限(DB)
  • CompletableFuture.allOf(cf1, cf2, cf3).join()
  • RT 从 150ms（串行）→ 50ms（并行），提升 3 倍
  • 每个异步任务 finally { UserContext.clear(); } 防泄漏

6.5 Seata TCC 分布式事务

实现 tcc/ 目录：

  • DocDeleteTccAction.java — TCC 接口（@TwoPhaseBusinessAction）
  • DocDeleteTccActionImpl.java — Try/Confirm/Cancel 实现
  • Try：逻辑删除文档 + Feign 调 audit-service 预插回收站+审计
  • Confirm：确认审计日志状态 SUCCESS
  • Cancel：恢复文档 + 删除回收站 + 取消审计

⚠️ 坑点：ctx.getActionContext("key") 返回 Object，必须用 getActionContext("key", Long.class) 获取类型化值。

面试要点：TCC 三大坑——幂等（Confirm/Cancel 重试）、空回滚（Try 未执行但 Cancel 被调）、悬挂（Cancel 先于 Try 到达）。

6.6 ShardingSphere 分库分表

实现：

  • config/ShardingConfig.java — 分片规则配置
  • 版本表按 doc_id % 4 分库 + 按 created_at 月份分表
  • application-sharding.yml — ShardingSphere 数据源配置

6.7 OT 版本增量存储

实现 ot/OtService.java：

  • 全量快照 + 增量补丁混合存储（每 10 版一个全量）
  • makePatch(old, new) → 生成 patch 文本
  • applyPatch(text, patchText) → 还原历史版本

⚠️ 坑点：org.bitbucket.cowwoc:diff-match-patch:1.2 使用 camelCase API（DiffMatchPatch.patchMake），非 Google 原版 snake_case（diff_match_patch.patch_make）。

6.8 RocketMQ 削峰 + 消息幂等

实现 mq/ 目录：

  • DocSyncMQProducer.java — 发送文档同步消息
  • DocSyncMQConsumer.java — 消费并同步到 ES
  • MessageIdempotentHandler.java — Redis SETNX 消息幂等

⚠️ 坑点：rocketmq-spring 2.3.0 的 @RocketMQMessageListener 不支持 consumeThreadMin 和 pullBatchSize 属性，只能用 consumeThreadMax。

6.9 自定义类加载器

实现 classloader/EncryptedClassLoader.java：

  • 继承 ClassLoader，重写 findClass()
  • 解密加密的 .class 文件字节码
  • 面试考点：双亲委派模型 + 打破双亲委派场景

6.10 版本 Diff 服务

实现 service/VersionDiffService.java：

  • java-diff-utils 4.12 生成 Unified Diff
  • DiffUtils.diff() 生成 Patch
  • UnifiedDiffUtils.generateUnifiedDiff() 生成文本

⚠️ 坑点：java-diff-utils 4.x 中 generateUnifiedDiff 在 UnifiedDiffUtils 类，不在 DiffUtils 类。

参考文件

  • zeus-doc-service-doc/src/main/java/com/zeus/doc/ 下全部 47 个文件
  • zeus-doc-service-doc/src/main/resources/（application.yml, application-sharding.yml, mapper XML）

Phase 7: 协同服务

学习目标

实现基于 Netty WebSocket 的实时协同编辑，OT 冲突合并，Leader 选举。

核心知识点

  • Netty WebSocket Server（ChannelInboundHandlerAdapter + WebSocketServerProtocolHandler）
  • OT（Operational Transformation）算法 — Diff-Match-Patch 三方合并
  • ZooKeeper Leader 选举（ ephemeral 节点 + watch）
  • 5 万+长连接的 Netty 调优（ChannelOption.SO_BACKLOG、EpollEventLoopGroup）

实现步骤

  1. NettyWebSocketServer.java：

    • BossGroup + WorkerGroup（NIO）
    • Pipeline: HTTP Codec → Aggregator → WebSocket Protocol → Custom Handler
    • 启动时绑定端口 8003

  2. OtMergeEngine.java：

    • merge(base, a, b) — 三方合并，返回 MergeResult(merged, conflict)
    • applyClientEdit(serverText, baseText, clientText) — 应用客户端编辑

Phase 13: 主从复制 + 读写分离（大纲案例8，面试重点）

学习目标

  • 亲手搭建 MySQL GTID 主从复制（docker 双实例）
  • 理解读写分离的三种实现层次：中间件（MyCat）/ ShardingSphere / Spring AbstractRoutingDataSource
  • 掌握”切面 Order 先于事务”的经典坑

核心知识点

  1. GTID vs 位点复制：MASTER_AUTO_POSITION=1 自动定位，无需 binlog 文件名/位点；
  2. 从库初始化三件事：等待主库 → 全量快照（mysqldump –set-gtid-purged=ON）→ CHANGE MASTER + START SLAVE；
  3. 应用层路由：AbstractRoutingDataSource.determineCurrentLookupKey() 每次 getConnection 时调用；
  4. 切面 @Order(HIGHEST_PRECEDENCE) 必须先于事务拦截器——事务在开始时拿连接，拿完路由就晚了；
  5. 一致性权衡：从库有延迟（最终一致），强一致场景不标 @ReadOnly 走主库。

实现步骤

  1. 主库加复制参数（server-id=1/log-bin/gtid-mode=ON），见 deploy/docker/docker-compose.yml mysql8；
  2. 主库 initdb 加 deploy/sql/05_master_slave_init.sql：创建最小权限复制账号 repl（只给 REPLICATION SLAVE, CLIENT）；
  3. 从库服务 mysql-slave（3307）：server-id=2 + GTID + –skip-log-bin；
  4. 从库 initdb 挂 deploy/sql/slave-init/01_slave_setup.sh：等待主库 → 等全部业务库存在（防竞态） → dump 快照导入 → CHANGE MASTER → START SLAVE；
  5. 应用层（file 服务）：
    • config/ReadOnly 注解 + DataSourceRouter（ThreadLocal）
    • MasterSlaveRoutingDataSource extends AbstractRoutingDataSource（含从库宕机回退主库）
    • DataSourceRouteAspect（@Order 最高，注解 + 方法名约定双路由）
    • MasterSlaveDataSourceConfig：@Primary 路由数据源（主=spring.datasource，从=zeus.datasource.slave）
  6. 单测：路由 key 切换 / 目标数据源解析 / 切面 finally 清理（src/test/.../config/ 下 3 个测试类）。

参考文件

  • compose：deploy/docker/docker-compose.yml（mysql8 + mysql-slave）
  • 脚本：deploy/sql/05_master_slave_init.sql、deploy/sql/slave-init/01_slave_setup.sh
  • 代码：zeus-doc-service-file/src/main/java/com/zeus/file/config/*
  • 验证：deploy/verify/verify-master-slave.sh

⚠️ 常见坑点（全部实测踩过）

  1. docker 同一容器路径挂两个 bind mount 会互相遮蔽：mysql8 曾同时挂 master-init 和 ../sql 到 /docker-entrypoint-initdb.d，后者被遮蔽 → schema 脚本静默不执行，从库 dump 时报 Unknown database 'zeus_doc' 才发现。规则：一个容器路径只挂一个卷。
  2. mysqladmin ping 通过 ≠ schema 就绪：从库脚本在主子初始化完成前 dump → Unknown database。必须显式等待”全部业务库存在”。
  3. docker-entrypoint 执行 initdb 时默认 USE MYSQL_DATABASE（zeus_user）→ 存储过程建到了 zeus_user，CALL 时找不到（1305）。跨库调用必须全限定：CALL zeus_audit_0.create_audit_monthly_tables(...)。
  4. 存储过程内未限定表名解析到过程定义库：CALL 时的 USE 不影响过程内部 → 月表全建到 _0 库。库名/表名分别反引号：`zeus_audit_0`.`doc_audit_202601`。
  5. MySQL 8.0.22+ 列名变更：SHOW REPLICA STATUS 输出 Replica_IO_Running / Seconds_Behind_Source（旧版 Slave_*），验证脚本需兼容两种。
  6. bash 变量名后紧跟全角括号（$VAR（）会被解析进变量名 → set -u 报 unbound。脚本内 $VAR 后接全角标点前加空格。

  2. mq/MqScenarioProducer：

    • sendDelayedRemind：syncSend 带 delayLevel（演示 10s 级）；
    • sendVersionOrderly：syncSendOrderly 以 docId 为 hashKey；
  3. mq/DelayedRemindConsumer：延迟提醒消费；zeus.mq.demo-fail=true 开关演示失败重试（教学性反例，默认关闭）；
  4. mq/VersionOrderlyConsumer：ConsumeMode.ORDERLY + 记录每个 docId 已消费最大版本号（顺序性监控）；

附录 A: 编译排坑全记录

以下是实际开发中遇到的所有编译错误及解决方案，按发现顺序记录。

A.1 ShardingSphere 依赖 artifact 错误

错误：Could not find artifact org.apache.shardingsphere:shardingsphere-jdbc:jar:5.4.1

根因：ShardingSphere 5.4.x 中 shardingsphere-jdbc 的 <packaging>pom</packaging>，是 POM 聚合器，没有 JAR。Maven Central 返回 404。

解决：改用 shardingsphere-jdbc-core（实际 JAR 包含所有 JDBC 功能）。

影响文件：pom.xml（父）、zeus-doc-service-doc/pom.xml、zeus-doc-service-audit/pom.xml

A.2 diff_match_patch API 版本不匹配

错误：程序包 name.fraser.neil.plaintext 不存在

根因：代码引用 Google 原版 name.fraser.neil.plaintext.diff_match_patch（snake_case），但 Maven 依赖 org.bitbucket.cowwoc:diff-match-patch:1.2 使用不同的包名和 camelCase API。

解决：重构为 cowwoc API：

  • diff_match_patch → DiffMatchPatch
  • patch_make() → patchMake()
  • patch_apply() → patchApply()
  • patch_toText() → patchToText()
  • patch_fromText() → patchFromText()（返回 List 而非 LinkedList，需 new LinkedList<>() 转换）
  • diff_main() → diffMain()

影响文件：OtService.java（doc）、OtMergeEngine.java（collab）

A.3 JacksonConfig 缺少静态 MAPPER

错误：RateLimitInterceptor.java:7 找不到符号 JacksonConfig

根因：JacksonConfig 在 com.zeus.common.config 包，但 RateLimitInterceptor 从 com.zeus.common.utils 导入。且 JacksonConfig 没有静态 MAPPER 字段。

解决：

  1. 修正 import 路径
  2. 在 JacksonConfig 中添加 public static final ObjectMapper MAPPER = buildMapper()

A.4 HotStats 内部 API 不可见

错误：程序包 jdk.internal.vm.annotation 不可见

根因：@jdk.internal.vm.annotation.Contended 是 JDK 内部 API，默认不可见，需 --add-exports 编译参数。

解决：移除 @Contended，改用手动 long 填充字段（7 个 long = 56 字节 + 对象头 8 字节 = 64 字节缓存行），无需 JVM 参数。

A.5 RejectedExecutionHandler 不是嵌套类

错误：ThreadPoolConfig.java:91 找不到符号

根因：代码写 ThreadPoolExecutor.RejectedExecutionHandler，但 RejectedExecutionHandler 是 java.util.concurrent 的顶层接口，不是 ThreadPoolExecutor 的嵌套类。

解决：添加 import java.util.concurrent.RejectedExecutionHandler 并直接使用。

A.6 RocketMQ 注解属性不存在

错误：DocSyncMQConsumer.java:31,33 找不到符号

根因：rocketmq-spring 2.3.0 的 @RocketMQMessageListener 不支持 consumeThreadMin 和 pullBatchSize 属性。

解决：移除这两个属性，仅保留 consumeThreadMax。

A.7 Seata getActionContext 类型转换

错误：java.lang.Object 无法转换为 java.lang.Long

根因：BusinessActionContext.getActionContext(String key) 返回 Object，不能直接赋给 Long。

解决：使用泛型版本 getActionContext("key", Long.class)。

影响文件：AuditTccActionImpl.java、RecycleBinTccActionImpl.java

A.8 MinIO expiry 方法签名

错误：java.time.Duration 无法转换为 int

根因：MinIO 8.5.11 的 GetPresignedObjectUrlArgs.Builder.expiry() 没有 Duration 重载，只有 expiry(int)（秒）。

解决：.expiry(Duration.ofSeconds(expireSeconds)) → .expiry(expireSeconds)

A.9 ES Analyzer 类包路径

错误：DocIndexInitializer.java:7 找不到符号 Analyzer

根因：ES 8.13.4 Java Client 中 Analyzer 类在 co.elastic.clients.elasticsearch._types.analysis 包，不在 co.elastic.clients.elasticsearch.indices 包。且原代码的 IndexSettingsAnalysisAnalyzer 类也不存在。

解决：import co.elastic.clients.elasticsearch._types.analysis.Analyzer

A.10 ES DateHistogramAggregation minDocCount 类型

错误：long 无法转换为 java.lang.Integer

根因：DateHistogramAggregation.Builder.minDocCount() 接受 Integer，1L 是 long 不能自动装箱。

解决：.minDocCount(1L) → .minDocCount(1)

A.11 Sentinel 熔断常量名

错误：SearchFallbackConfig.java:75 找不到符号 DEGRADE_GRADE_SLOW_REQUEST_RATIO

根因：Sentinel 该版本中慢调用比例熔断的常量是 RuleConstant.DEGRADE_GRADE_RT，不是 DEGRADE_GRADE_SLOW_REQUEST_RATIO。

解决：DEGRADE_GRADE_SLOW_REQUEST_RATIO → DEGRADE_GRADE_RT

A.12 java-diff-utils generateUnifiedDiff 方法位置

错误：VersionDiffService.java:45 找不到符号 generateUnifiedDiff

根因：java-diff-utils 4.x 中 generateUnifiedDiff 在 UnifiedDiffUtils 类，不在 DiffUtils 类。

解决：DiffUtils.generateUnifiedDiff(...) → UnifiedDiffUtils.generateUnifiedDiff(...)

A.13 系统默认 JDK 是 1.8，但项目要求 17

错误：java -version 显示 1.8，mvn 编译报 invalid target release: 17。

根因：Maven 用 JAVA_HOME 决定编译 JDK；系统 PATH 里的 java 是 1.8，但 /usr/local/bin/mvn 可能已绑定 17（mvn -version 会显示 runtime）。两处不一致。

A.14 类加载器测试用”测试类自身字节码”冒充目标类 → defineClass 报 wrong name

错误：EncryptedClassLoaderTest 运行报 NoClassDefFoundError ... (wrong name: com/zeus/template/HelloTemplate)。

根因：测试原实现读取测试类自身的 .class 作为模板素材，但字节码内部类名是 com.zeus.doc.classloader.EncryptedClassLoaderTest，defineClass("com.zeus.template.HelloTemplate", ...) 校验类名不匹配直接抛错——这个测试从未真正跑过（此前只 compile 未 test）。

解决：新建真实夹具类 src/test/java/com/zeus/template/HelloTemplate.java，测试从 classpath 读取它的字节码（类名与字节码内部名一致）。

影响文件：EncryptedClassLoaderTest.java、HelloTemplate.java（test 目录）
经验：每写一个测试就立刻跑；mvn compile 通过 ≠ 测试可运行，很多”从没跑过”的测试藏着致命问题。

A.15 单测里 pjp.proceed() 抛的是 Throwable 不是 Exception

错误：mockPjp(...) throws Exception 编译报”未报告的异常错误 java.lang.Throwable”。

根因：ProceedingJoinPoint.proceed() 签名是 throws Throwable，throws Exception 无法覆盖。

解决：签名改为 throws Throwable。

影响文件：DataSourceRouteAspectTest.java
