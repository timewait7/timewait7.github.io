2. 创建隔离 VM（推荐方式）

2.1 为什么必须做隔离

Lima 默认会把宿主机的 $HOME 目录以只读方式挂载进 VM（macOS 路径为 /Users/<用户名>）[reference:4]。如果你在 VM 里执行 chmod、chown 或对挂载目录进行写操作，会直接影响 Mac 上的真实文件。虽然默认是只读，但一旦用 --mount-writable 或 --mount-only 加了可写目录，风险就出现了。

安全建议：练习 rm -rf、crontab -r、find -delete 等危险命令时，不要使用默认挂载。Lima 官方明确提供了 --mount-none 来完全禁用宿主挂载[reference:5]。

2.2 三种挂载策略

策略 命令参数 效果 适用场景
完全隔离 --mount-none VM 内看不到任何 Mac 目录 练习危险命令、不想有任何穿透风险
只读挂载 home 默认行为（不加参数） VM 内可读 Mac 的 $HOME，但不能写 需要在 VM 里读 Mac 上的文件，但不希望被改
只挂载指定目录 --mount-only "$HOME/lima-share:w" 只映射一个共享目录，可写 需要在 Mac 和 VM 之间频繁交换文件

2.5 资源限制（防止 VM 拖垮 Mac）

默认配置大约是 4 CPU / 4 GiB 内存 / 100 GiB 磁盘[reference:8]。如果你的 Mac 内存不大，或者同时开着 IDE、Docker，建议显式限制：

参数 含义 建议值（练习场景）
--cpus 分配的核心数 2（足够跑 top/vmstat/jstack）
--memory 内存 GiB 4（练习命令不需要大内存）
--disk 磁盘 GiB 20（装工具 + 造测试文件够用）

6.3 建议的练习顺序（对应你的手册）

顺序 练什么 VM 内验证方式
1 top / vmstat / free 用 yes > /dev/null & 造 CPU 负载，观察 top 和 vmstat[reference:14]
2 df / du / lsof 用 fallocate 造大文件，rm 后用 lsof +L1 验证空间未释放
3 grep / awk / sort / uniq 自造 Nginx 格式日志，跑一遍 TOP 接口统计管道
4 systemctl / journalctl 管理 cron 或 ssh 服务，看日志
5 crontab 加一条每分钟任务，用 journalctl -u cron 确认调度
6 jstack / jstat 在 VM 内跑一个死循环 Java 程序，用 top -Hp → jstack 定位
7 ss / tcpdump / dig 用 nc -l 起监听，ss -lntp 确认，tcpdump 抓握手

7. 常见问题与排障

7.1 limactl shell lab 报错「实例不存在」

如果从未创建过名为 lab 的实例，limactl shell lab 会直接报错。limactl shell 只认实例名，不认模板名[reference:15]。

7.2 误在共享目录里执行了删除

如果 VM 使用 --mount-only 挂载了可写目录，且你在该目录里执行了 rm -rf，Mac 上的对应文件已被删除。这是 --mount-only 的固有风险。练习危险命令请一律使用 --mount-none 的实例。

7.3 VM 启动卡住或性能差

  • 确认使用的是 VZ 驱动（Lima 在 macOS 13.5+ 默认启用）。如果手动指定了 --vm-type=qemu，在 Apple Silicon 上会慢很多[reference:16]。
  • 检查资源是否给得太少：--cpus=2 --memory=4 是练习场景的合理下限。
  • 磁盘 IO 慢：避免在挂载目录里做大量文件操作，把测试数据放在 VM 原生文件系统（/tmp 或 ~/）里，性能差距可达数倍。

最后提醒：Lima 官方文档明确警告可能存在导致数据丢失的 bug，尤其是共享可写目录和 VM 镜像升级场景[reference:19]。练习环境里不要存放唯一副本的重要数据；危险命令一律在 --mount-none 的实例中执行。
